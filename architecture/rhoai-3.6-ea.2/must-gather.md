## Purpose

**Short**: Collects OpenShift and Kubernetes cluster, namespace, resource, Helm, and workload-log data for Red Hat OpenShift AI troubleshooting.

**Detailed**: `odh-must-gather` is an image executed by `oc adm must-gather` or as a Kubernetes Job. Its entrypoint detects the cluster distribution, selects `oc` or `kubectl`, establishes configurable RHOAI namespaces, and dispatches collectors for platform components such as KServe, notebooks, data science pipelines, Kueue, KubeRay, TrustyAI, AI Gateway, MCP Lifecycle Operator, and OGX. The OpenShift path also records the RHOAI version and inspects operator, monitoring, application, gateway, Kuadrant, and Helm namespaces.

For xKS environments, collection is focused on LLM-D/RHAII. The collector gathers cluster-scoped resources and node information, inspects selected namespaces, discovers namespaces containing LLMInferenceService resources, collects Gateway API and inference-extension resources, and optionally gathers workload-variant-autoscaler and batch-gateway data. Collection is diagnostic and read-only from the cluster; it writes gathered YAML, logs, manifests, and metadata below `must-gather` in the execution environment.

## Architectural Analysis

The image is a thin orchestration layer over upstream OpenShift must-gather images. The Konflux Dockerfile preserves the original `/usr/bin/gather` as `gather_original`, replaces it with this repository's dispatcher, adds `kubectl` from an OpenShift CLI builder image, and copies the repository's `helm` binary and Bash collection scripts into the image. The alternate xKS `Containerfile` starts from an upstream origin must-gather image and downloads architecture-specific `kubectl` and Helm binaries during the build.

Collection has two control planes: `gather.sh` performs distribution detection and OpenShift/RHOAI setup, while `xks_util.sh` supplies kubectl-based inspection and auto-discovery for non-OpenShift clusters. The OpenShift `all` path launches most component collectors concurrently, so a failure in one component does not necessarily prevent the overall report from completing. This improves collection time but creates partial-output semantics; the final console summary reports failed jobs but the artifact itself has no completeness manifest.

The principal architectural risks are supply-chain reproducibility for the xKS downloads (URLs are versioned but not checksum-pinned), broad read privileges required by must-gather, and potentially sensitive diagnostic output such as pod logs and resource YAML. Namespace and component selection is configurable, but the default OpenShift path intentionally spans operator, application, monitoring, notebook, model registry, gateway, Kuadrant, and Helm namespaces. The analyzer baseline extracted one container entrypoint but marked CRDs, services, endpoints, gRPC, webhooks, and several cross-cutting areas as not verified; the empty tables below therefore reflect source review, not a claim that analyzer coverage proves absence.
