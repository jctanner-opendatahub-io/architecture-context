## Purpose

**Short**: Routes disaggregated LLM inference requests through a decoder and an optional prefill worker.

**Detailed**: The sidecar exposes an OpenAI-compatible HTTP surface and forwards ordinary requests to a local vLLM decoder. Chat and completion requests that include a prefill target header are handled by a P/D connector (NIXL v2 by default) before the request is sent through the decoder path.

The optional SSRF protection mode watches one namespace-scoped `InferencePool` and matching pods through the Kubernetes API. It maintains an allowlist of pod IPs and names and rejects prefill targets outside that allowlist. The repository is deprecated; its implementation has moved to `llm-d/llm-d-inference-scheduler` (`cmd/pd_sidecar` and `pkg/sidecar`) according to README.md.

## Architectural Analysis

This is a single Go binary with two proxy planes: a decoder reverse proxy and dynamically cached prefill reverse proxies. The request router intercepts `/v1/chat/completions` and `/v1/completions`, extracts the prefill target from `x-prefiller-host-port` (with a legacy `x-prefiller-url` fallback), and otherwise passes traffic through to the decoder. TLS can be enabled independently for the client-facing proxy, decoder, and prefill connections.

The optional allowlist is a useful application-level SSRF boundary: it scopes the `InferencePool` and pod watches to a configured namespace and pool name, then derives targets from selected pods. It is disabled by default, in which case prefill requests are allowed for backward compatibility. The supplied deployment manifests have unresolved wiring issues: the Service selector does not match the StatefulSet pod label, the Service targets 8080 while the program defaults to 8000, and the SSRF RBAC manifest is not included by the root kustomization and binds a placeholder service account.
