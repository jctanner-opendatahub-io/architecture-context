## Purpose

**Short**: Provides intelligent inference request routing using endpoint, load, priority, and KV-cache signals.

**Detailed**: The llm-d Router combines an Endpoint Picker (EPP) with optional Envoy or Gateway API data-plane integration. EPP receives Envoy External Processing requests over gRPC, evaluates inference-pool endpoints using configurable scheduling, flow-control, request-control, data-layer, and parser plugins, and returns routing decisions.

The repository also contains the InferenceObjective and InferenceModelRewrite APIs and reconcilers, an InferencePool/Pod discovery path, an asynchronous coordinator, and a disaggregation sidecar. Standalone mode can run Envoy as an EPP sidecar or separate service; Gateway mode integrates the EPP with an existing Gateway API implementation. The sidecar coordinates prefill/decode and encode/prefill/decode inference phases.

## Architectural Analysis

This is a multi-binary Go repository rather than a single deployable. The EPP is the control-plane-aware routing brain, while Envoy or another Gateway API implementation remains responsible for request data-plane handling. The EPP watches namespaced inference resources and pods, so its effective routing view is tied to an InferencePool namespace and to the RBAC granted to its service account.

The architecture separates request scheduling from model-serving workers and supports pluggable scorers, filters, tokenizers, and data sources. In-memory and Redis-backed KV-cache indexing, ZMQ KV events, OpenTelemetry tracing, and Prometheus metrics provide operational and performance signals. A key deployment risk is configuration-dependent transport security: gRPC TLS is enabled by default in EPP options but certificates, minimum version, cipher suites, and verification behavior are deployment inputs.
