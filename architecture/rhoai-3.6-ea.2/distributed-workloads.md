## Purpose

**Short**: Integration tests, examples, benchmarks, and container images for distributed machine-learning workloads on OpenShift AI.

**Detailed**: The repository validates and demonstrates distributed workloads using Kubeflow Training Operator v1, Kubeflow Trainer v2, KubeRay, Kueue, and JobSet. Go test infrastructure provides Kubernetes, OpenShift, Kubeflow, Ray, queueing, metrics, and lifecycle helpers; Python examples implement training and data-processing workloads.

It also builds CPU, CUDA, and ROCm runtime/universal images containing PyTorch, OpenMPI, Ray, and training libraries. Example manifests package MinIO-backed storage, NFS workshop infrastructure, and a KServe ServingRuntime for Stable Diffusion. It is not itself a long-running platform controller.

## Architectural Analysis

This is a validation and workload-harness repository with four cooperating layers: shared Go test support, suite-specific integration tests, runnable examples/benchmarks, and accelerator-specific container images. The Go module intentionally carries both legacy Training Operator v1 and Trainer v2 dependencies, allowing migration coverage while the newer TrainJob path is exercised alongside PyTorchJob tests.

The repository deploys resources directly from example and workshop YAML rather than a product kustomize base. Namespace and ServiceAccount boundaries are supplied by the target cluster and test configuration. MinIO and S3-compatible storage are common data-plane dependencies, while Kubernetes API access is the control-plane integration. Dynamic Python routes, call graphs, and some shell entrypoint behavior are not fully resolved by the analyzer.

The release branch contains both current AIPCC-backed images and a Konflux ROCm 6.4 image reference. Overlay 0017 marks ROCm 6.4 retired and ROCm 7.14 current, so that runtime image is a supply-chain/release maintenance risk rather than evidence of current supported accelerator posture.
