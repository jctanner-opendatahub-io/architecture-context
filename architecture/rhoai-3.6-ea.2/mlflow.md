## Purpose

**Short**: MLflow is an open-source AI engineering platform for agents, LLMs, and model lifecycle management with built-in observability, evaluation, and optimization capabilities.

**Detailed**: MLflow provides a comprehensive platform for managing the complete ML lifecycle, including experiment tracking, model versioning and deployment, LLM observability with tracing, model evaluation, and prompt management. The RHOAI-specific distribution includes production-grade features for AI applications with workspace-aware deployments, Kubernetes integration, and multi-tenant support. The platform handles artifact storage, experiment management, model serving configuration, and integrates with external LLM providers (OpenAI, Anthropic, AWS Bedrock, Cohere, Mistral, and others) for evaluation and optimization workflows.

## Architectural Analysis

MLflow is a multi-component Python service architecture organized into modular libraries: the core MLflow platform (FastAPI-based server), MLflow Skinny (minimal-dependency client), and MLflow Tracing SDK (lightweight instrumentation). The RHOAI distribution emphasizes workspace-scoped deployments with Kubernetes storage backends (`kubernetes://` URI scheme), enabling multi-tenant deployments where each workspace maintains isolated experiment and model registries.

The Dockerfile uses multi-stage builds: a Node.js stage for React UI compilation, a Python builder stage for wheel packaging with hermetic Konflux requirements, and a minimal UBI9 runtime stage. The build leverages Konflux/Cachi2 for hermetic dependency resolution with cryptographic hash verification. Build inspection shows awareness of cryptographic libraries (cryptography v46.0.7 pinned), though no explicit FIPS compliance environment variables are present—compliance relies on inherited UBI9 base image properties and OpenSSL integration.

The service exposes 48+ HTTP REST endpoints across `/ajax-api/` and `/api/` prefixes, handling experiment/run management, model registry operations, job scheduling, artifact serving, and AI Gateway features (prompt management, evaluations). External integrations reference API tokens for LLM providers via environment variables, creating a significant credential management surface. The architecture includes an internal MLflow Gateway service for LLM request routing and cost control. Authentication is application-level (Bearer tokens, session cookies) with workspace-scoped RBAC filtering.
