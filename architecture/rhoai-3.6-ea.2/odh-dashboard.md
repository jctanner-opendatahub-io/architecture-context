## Purpose

**Short**: Provides the OpenShift AI web console, its federated plugin backends, and the operator/controller resources that make dashboard capabilities available.

**Detailed**: The repository is a monorepo containing a React/TypeScript host application, a Fastify backend that serves static assets and proxies API and WebSocket traffic, and multiple Go backend-for-frontend (BFF) modules. Federated modules cover capabilities including agent operations, AutoML, AutoRAG, data registry, evaluation, generative AI, MaaS, MLflow, model registry, and notebooks.

It also contains the dashboard operator and Kubeflow Workspaces controller components. These reconcile the cluster-scoped Dashboard, namespaced Workspace, and cluster-scoped WorkspaceKind APIs, create dashboard-related platform resources, and expose validating/conversion webhooks. The BFF layer uses Kubernetes clients and SubjectAccessReview/TokenReview-style checks to apply the caller's cluster permissions when accessing tenant-scoped platform services.

## Architectural Analysis

This is a platform-surface monorepo rather than a single runtime. The primary user path is a federated React host through the Fastify backend, with Go BFFs providing capability-specific APIs and proxying to Kubernetes and platform services. The operator is a separate control-plane artifact: it reconciles the Dashboard CR and creates or manages the services, RBAC, routes, workloads, and supporting resources required by enabled dashboard modules.

The repository combines cluster-scoped platform orchestration with namespace-scoped workspace resources. That split is intentional but high privilege: the dashboard operator can manage workload, RBAC, networking, route, OAuth, storage, and platform CRD resources. BFFs mitigate cross-namespace access by forwarding user identity and making access-review calls, but the analyzer reports incomplete authentication and dynamic endpoint coverage; those surfaces should remain review targets.

TLS handling is stronger than a default-only implementation in the shared Go code. The dashboard derives server TLS settings from the OpenShift cluster TLS security profile, defaults to an Intermediate profile, fails closed when in-cluster configuration cannot be loaded, and uses system trust material in the Node backend. Konflux Go builds include `CGO_ENABLED=1` and `-tags strictfipsruntime` in at least the core BFF Dockerfile, but a repository-wide FIPS posture is not verified by the analyzer.
