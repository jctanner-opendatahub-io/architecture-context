## Purpose

**Short**: Prism is an interactive dashboard for collecting, validating, comparing, and analyzing distributed-inference benchmark results.

**Detailed**: The React 19/Vite application unifies benchmark data from Google Cloud APIs, Google Cloud Storage, Amazon S3, Google Drive-derived archives, local files, and the llm-d Results Store. Dashboards present throughput, latency, cost, quality, regressions, routing, prefix-cache, workload, and agentic-serving views.

The Express server is both the static-asset server and a BFF. It provides configuration, OAuth, Results Store lifecycle APIs, local-development file APIs, and authenticated proxies to Google APIs. It obtains Google credentials with Application Default Credentials (ADC), keeps cloud credentials server-side for proxied calls, and applies API rate limiting.

## Architectural Analysis

Prism is a single deployable web application with two cooperating runtime surfaces: a Vite-built React SPA and an Express process that serves the SPA and its `/api` surface. The BFF centralizes Google Cloud authentication and proxies GIQ and GCS requests, while the browser directly reads public S3/GCS sources where configured. This gives the UI one relative API namespace but creates a mixed trust model: some data paths use server ADC, some use a user-provided bearer token, and some are intentionally public.

The Results Store is a GCS-backed workflow. Submissions are authenticated with GitHub OAuth, written to a configured bucket/prefix, validated and processed, then exposed through owner/role-aware list, read, review, export, and delete endpoints. Playground mode deliberately relaxes these checks. The Dockerfile uses a development stage, a frontend build stage, and a production Node runtime stage; the production image is not a minimal static image because it retains the Express server and production npm dependencies.
