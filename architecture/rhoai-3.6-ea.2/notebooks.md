## Purpose

**Short**: Builds and publishes OpenDataHub/OpenShift AI Jupyter workbench and Elyra pipeline-runtime images.

**Detailed**: The repository assembles reusable notebook layers (minimal, baseline, data-science, PyTorch, TensorFlow, TrustyAI, and accelerator variants), a code-server workbench, and runtime images used to execute pipeline nodes. Images are based on pinned Konflux build inputs, install Python wheels from prefetched lockfiles, and run as UID 1001.

The ODH and RHOAI manifest trees publish these images as OpenShift ImageStreams. RHOAI uses `registry.redhat.io/rhoai/*` image sources and retains historical tags, while ODH uses `quay.io/opendatahub/*`; the repository itself does not deploy notebook pods or provide the notebook-controller control plane.

## Architectural Analysis

This is an image factory with two related product surfaces: interactive Jupyter/code-server workbenches and lightweight Elyra pipeline runtimes. Multi-stage Dockerfiles share a CPU, CUDA, or ROCm base and then add a locked package set and startup scripts. The same source hierarchy is reused across CPU and accelerator builds, keeping image naming and manifest metadata consistent while allowing hardware-specific packages and paths.

The deployment contract is intentionally indirect. ImageStreams and their generated parameter ConfigMaps are consumed by platform controllers, while notebook pods, services, authentication, storage, and user tenancy are supplied by the notebook controller/platform. Consequently, this repository’s Kubernetes surface is primarily image metadata rather than an independently deployable service.

## Sub-Component Details

### Jupyter workbench images

**Dockerfiles**: `jupyter/{minimal,baseline,datascience,pytorch,tensorflow,trustyai}/ubi9-python-3.12/Dockerfile.konflux.*` and ROCm variants
**Intent**: Build interactive notebook images from common Jupyter layers. `start-notebook.sh` is the container entrypoint; accelerator images expose the corresponding device libraries and environment.
**Image**: `quay.io/opendatahub/odh-workbench-jupyter-*` or `registry.redhat.io/rhoai/odh-workbench-jupyter-*`
**Language**: Python plus packaged Jupyter/Node tooling
**Port**: Not declared in these Dockerfiles; runtime notebook port is supplied by the notebook-controller deployment.

### Code-server workbench

**Dockerfile**: `codeserver/ubi9-python-3.12/Dockerfile.konflux.cpu`
**Intent**: Packages code-server, Node.js 22, Python dependencies, extensions, and nginx configuration for browser-based workbenches.
**Image**: `odh-workbench-codeserver-datascience-cpu-py312-ubi9`
**Language**: Python and JavaScript/TypeScript
**Port**: Not declared; runtime service mapping is supplied by the platform controller.

### Elyra pipeline runtimes

**Dockerfiles**: `runtimes/*/ubi9-python-3.12/Dockerfile.konflux.*`
**Intent**: Provide non-interactive images for pipeline execution; `ELYRA_INSTALL_PACKAGES=false` prevents runtime package mutation and a bundled bootstrapper supports KFP execution.
**Image**: `quay.io/opendatahub/odh-pipeline-runtime-*` or corresponding RHOAI registry image
**Language**: Python
**Port**: None identified.
