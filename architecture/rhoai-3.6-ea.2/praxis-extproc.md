## Purpose

**Short**: Runs Praxis filter pipelines as an Envoy External Processing gRPC service for model-serving gateway traffic.

**Detailed**: `praxis-extproc` translates Envoy External Processing protocol streams into Praxis filter-pipeline executions and translates the results back into Envoy processing responses. It can inspect and mutate request/response headers, bodies, and trailers, and supports streamed and buffered processing modes.

In the RHOAI MaaS deployment, the same binary is instantiated as a pre-processing service for lightweight model extraction before authorization and as a post-processing service for the full inference processing pipeline. Envoy gateway filters call the services over HTTP/2 gRPC; the service itself does not expose a user-facing HTTP API.

The process also exposes a separate gRPC health listener and an unauthenticated HTTP Prometheus metrics listener. YAML configuration is mounted from a ConfigMap, while the binary supports plaintext, ephemeral self-signed TLS, or provided-certificate TLS with optional mTLS.

## Architectural Analysis

This is a deliberately thin, stateless data-plane adapter: Envoy owns ingress, routing, and connection-cluster configuration, while Praxis owns filter-chain composition and request mutation. The main listener is a bidirectional `ExternalProcessor.Process` stream, allowing the service to preserve Envoy phase ordering across headers, body chunks, and trailers. A shared pipeline is built once at startup and used concurrently for streams.

The RHOAI overlay composes two logical instances from one image and base Deployment. The pre-processing instance runs before the platform authorization filter and is configured to fail open; the post-processing instance runs after authorization and fails closed. This ordering and the `EnvoyFilter` anchor compatibility logic are central to the component's integration contract.

The release build is multi-stage and digest-pinned in `Dockerfile.konflux`, uses system OpenSSL rather than vendored OpenSSL, and runs as UID 1001 with a read-only root filesystem and dropped capabilities. However, the deployment's default self-signed TLS plus `insecureSkipVerify: true` DestinationRule is an intentional trust model for gateway-to-service traffic, not a general certificate-validation posture.
