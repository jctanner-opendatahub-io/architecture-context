## Purpose

**Short**: Provides the Praxis Policy Engine (PPE), a typed, phased Rust runtime that evaluates identity, authorization, delegation, data-control, and approval policies for agent traffic.

**Detailed**: PPE is a library consumed by a host gateway or proxy; it is not itself a Kubernetes operator, controller, or standalone workload. The `PolicyEngine` loads trusted YAML configuration, constructs configured plugins, and dispatches requests through a five-phase execution model. The public facade can expose the core runtime alone or feature-gated builtin extensions.

The workspace includes an APL compiler/evaluator and bridges between APL attributes and PPE hooks. Builtins cover JWT identity resolution, RFC 8693 OAuth token exchange, OIDC CIBA approval, Cedar/CEL/OPA decision points, and an optional Valkey/Redis session store. Reference-only plugins demonstrate audit logging and PII scanning. Outbound HTTP is deliberately a host-provided `HttpTransport`, allowing the embedding gateway to own pooling, TLS trust, egress policy, and tracing.

## Architectural Analysis

The repository is a modular policy enforcement plane rather than a deployable service. `praxis-policy` is the host facade; `praxis-policy-core` owns lifecycle, registries, hook dispatch, configuration, and the five execution phases; APL crates compile and evaluate policy documents; and feature-gated builtin crates supply security integrations. This separation lets a host replace any plugin while preserving a common hook and payload contract.

The main trust boundary is configuration-to-runtime: the loader supplies authoritative plugin configuration to the engine and executor, while plugins do not supply their own configuration. A second boundary is host-to-library: the host supplies HTTP transport, identity/context extensions, and deployment controls. Consequently, network exposure, Kubernetes authorization, TLS provider selection, and operational tenancy are properties of the embedding host and cannot be inferred from this repository.

The design has useful fail-closed properties: missing identity context can produce an explicit violation, outbound transport failures are represented as errors, and the Valkey session store treats backend errors as failures while accepting only confirmed key misses as empty state. Security risk remains configuration-sensitive: inline client secrets are supported for development, plaintext endpoints require an explicit opt-in, and the dependency graph contains both `aws-lc-rs` and `ring`; static dependency presence does not establish FIPS validation or runtime provider selection.
