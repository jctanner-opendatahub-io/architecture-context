## Purpose

**Short**: Manages ModelRegistry, Catalog, and AIHub resources and reconciles their backing services, databases, authentication, and ingress resources.

**Detailed**: The operator exposes namespaced `ModelRegistry` resources and provisions a model-registry REST service backed by PostgreSQL or MySQL. It can create an in-cluster PostgreSQL deployment, database service, TLS material references, NetworkPolicies, per-registry RBAC, and Gateway API or OpenShift Route exposure.

The repository also contains the catalog and AIHub controllers. The catalog controller manages a shared model catalog with its own PostgreSQL backend, service, kube-rbac-proxy, and validating/mutating webhook. The AIHub controller coordinates cluster-scoped AIHub configuration and catalog resources. Controller-runtime admission webhooks default and validate ModelRegistry objects, while the CRD conversion webhook supports `v1alpha1` and `v1beta1`.

## Architectural Analysis

This is a multi-surface Go operator rather than a single deployment controller: the default manager, catalog overlay, and AIHub overlay select different reconcilers and manifests. ModelRegistry instances are namespace-scoped, but the manager has cluster-wide permissions to create and delete their workloads, routes, NetworkPolicies, RBAC, and OpenShift Groups. The resulting architecture delegates tenant authorization to Kubernetes RBAC and kube-rbac-proxy while keeping database isolation primarily at the namespace/instance level.

The primary RHOAI 3.x path uses Gateway API HTTPRoutes and a kube-rbac-proxy sidecar on port 8443, while OpenShift Routes remain available for the alternate/legacy route mode. Database TLS and proxy TLS are secret-driven. Runtime TLS for the operator's webhook and metrics endpoints is derived from the cluster TLS profile when the OpenShift config API is available; exact application cipher behavior is otherwise platform-configured.

Analyzer coverage is partial for dynamic HTTP endpoints, Services, authentication, integration points, and webhook registration; dynamic route construction and unresolved image transforms should therefore be treated as incomplete rather than absent.
