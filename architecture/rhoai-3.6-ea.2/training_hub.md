## Purpose

**Short**: Training Hub provides one Python API for supervised, continual, parameter-efficient, reinforcement, prompt-optimization, and embedding fine-tuning workflows.

**Detailed**: The package presents algorithm functions and classes such as `sft`, `osft`, `lora_sft`, `lora_grpo`, `grpo`, `gepa`, and `embedding_sft`. An `AlgorithmRegistry` maps each algorithm to a backend implementation, allowing callers to select a training engine without changing the public algorithm interface (`src/training_hub/algorithms/__init__.py:6-96`).

Training is executed in the caller's Python process and delegated to external training frameworks. The supported paths include InstructLab Training for SFT, RHAI Innovation Mini-Trainer for OSFT, Unsloth/TRL for LoRA, OpenPipe ART or verl for GRPO, GEPA or MLflow for prompt optimization, and SentenceTransformers for embedding fine-tuning. It consumes local paths or Hugging Face/dataset inputs and writes checkpoints, processed data, metrics, and model artifacts to caller-selected output directories.

## Architectural Analysis

Training Hub is an orchestration and compatibility layer rather than a control-plane component. Algorithm classes normalize public parameters, translate selected names (for example `max_tokens_per_gpu` to InstructLab's `max_batch_len`), and invoke backend-specific trainers. Backend imports are intentionally often lazy, so optional capabilities such as CUDA, Unsloth, ART, verl, GEPA, MLflow, and SentenceTransformers are loaded only when selected.

The principal architectural boundary is between the stable Training Hub API and rapidly changing ML frameworks. Distributed SFT and OSFT use `torchrun` parameters with argument-over-environment precedence and support multi-node rendezvous (`src/training_hub/utils.py:34-228`). LoRA/GRPO combines PEFT-style adapters with either co-located inference/training or Ray/FSDP/vLLM orchestration. A unified callback abstraction is bridged into backend-native callbacks; callback payloads cross torchrun subprocess boundaries through class-source serialization (`src/training_hub/callbacks.py:1-115`, `src/training_hub/adapters/serialize.py:1-158`).

Because this checkout contains no container build, Kubernetes manifest, server startup, or network listener, deployment, ingress, RBAC, and tenant isolation are delegated to the environment and selected third-party frameworks. The package can nevertheless initiate outbound model and LLM API calls through its dependencies, especially the GEPA and ART/rollout paths.
