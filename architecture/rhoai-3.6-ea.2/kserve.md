## Purpose

**Short**: KServe is a standardized, distributed platform for scalable, multi-framework deployment of generative and predictive AI inference workloads on Kubernetes.

**Detailed**: KServe provides a unified inference serving platform supporting both generative AI (LLMs via vLLM/llm-d with OpenAI-compatible protocols) and predictive AI (multi-framework: TensorFlow, PyTorch, scikit-learn, XGBoost, ONNX, and others). The platform enables intelligent request routing between predictor/transformer/explainer components, canary deployments via InferenceGraph, request-based autoscaling with scale-to-zero, model explainability, and performance optimization. Within RHOAI, KServe operates as a controller-based operator managing InferenceService and LLMInferenceService custom resources, handling model deployment lifecycle, routing, scaling, and storage integration across diverse inference workload patterns.

## Architectural Analysis

KServe is structured as a **multi-controller Kubernetes operator** with clear separation of concerns across controllers. The architecture employs controller-runtime for standard Kubernetes patterns and integrates deeply with cloud-native ecosystem components (Istio, Gateway API, KEDA, Knative).

**Key patterns**:

1. **Multi-version API evolution**: Maintains v1alpha1, v1alpha2 (LLM), and v1beta1 (InferenceService) APIs concurrently with conversion webhooks, enabling gradual deprecation and version migration.

2. **Sidecar injection and pod mutation**: Admission webhooks mutate Pod specs to inject storage initializers, accelerator configurations, and TLS certificates; enables heterogeneous hardware support (NVIDIA CUDA, AMD ROCm, Intel Gaudi, IBM Spyre).

3. **Distributed TLS infrastructure**: Manages TLS at webhook layer (server certificates in Secrets, rotation via cert-manager), component-to-Envoy mTLS (self-signed, enforced via DestinationRule), and external traffic encryption (Gateway API + kube-rbac-proxy).

4. **Multi-model runtime abstraction**: 25+ ClusterServingRuntime resources define model frameworks (TensorFlow, scikit-learn, ONNX, vLLM, etc.), each with corresponding container images; controllers bind InferenceServices to runtimes and instantiate serving containers.

5. **Stateful workload coordination**: LocalModelNode and LocalModelCache controllers manage per-node model caching, coordinating Pods, PVs, and Jobs to pre-fetch models and reduce cold-start latency.

6. **Build-time FIPS enforcement**: Manager controller uses `GOEXPERIMENT=strictfipsruntime CGO_ENABLED=1` flags in Dockerfile, ensuring dynamically-linked OpenSSL and FIPS-compliant cryptography in RHOAI environments.

## Multi-Tenancy

### Tenant Model

| Aspect | Value | Source |
|--------|-------|--------|
| **Tenant boundary** | Per-namespace (InferenceService, LLMInferenceService are Namespaced CRDs) | CRD scope definitions |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Kubernetes RBAC per namespace; kube-rbac-proxy on ingress | Kubernetes RBAC + kube-rbac-proxy | Inference endpoint auth is app-defined (not KServe-enforced) |
| Data storage | Per-namespace PVCs (model caching); per-tenant cloud storage paths/IAM | Kubernetes + cloud provider | Shared object storage requires tenant-scoped paths or IAM policies |
| Network traffic | No default NetworkPolicy; optional Istio AuthorizationPolicy | Kubernetes / Istio (user-configured) | No built-in NetworkPolicy; platform must configure |
| Compute & resources | Kubernetes ResourceQuota per namespace (optional) | Kubernetes | No default ResourceQuota; user must configure |
| Configuration & secrets | Per-namespace Secrets (model credentials, cloud API keys) | Kubernetes | Cross-namespace access requires explicit RBAC grants |
| API scoping | Namespace-scoped API watches by default | Controller config | Controllers watch all namespaces; single instance shared across tenants |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| ClusterServingRuntime (shared ML frameworks) | Cluster-wide (not tenant-isolated) | No hard isolation; all InferenceServices using same runtime share definition |
| Ingress / Gateway infrastructure | Per-InferenceService (each gets own Ingress/Route/HTTPRoute) | Kubernetes namespace scoping |
| Model storage (S3, Azure, GCS) | Per-InferenceService (storage creds in Secrets) | Cloud provider IAM (if scoped per tenant) or Secret-level isolation |
| Kubernetes API Server | API-level via RBAC | Kubernetes RBAC (RoleBindings scope who can create/read CRs) |
