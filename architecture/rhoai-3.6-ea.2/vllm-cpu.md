## Purpose

**Short**: CPU-only vLLM image providing a high-throughput, OpenAI-compatible HTTP inference server.

**Detailed**: vllm-cpu is a downstream packaging of vLLM, an inference engine for large language models. It loads local or remote Hugging Face/ModelScope model repositories, performs tokenization and model execution through PyTorch and CPU-specific native kernels, and exposes OpenAI-compatible plus task-specific REST APIs.

The Konflux CPU image is a single runtime image whose entrypoint is `vllm.entrypoints.openai.api_server`. It is designed to be consumed as a model-serving runtime by the surrounding RHOAI/KServe deployment layer; this repository contains no Kubernetes operator or deployment manifests.

## Architectural Analysis

The architecture separates a dependency-heavy builder stage from a minimal runtime stage. The builder creates a Python 3.12 virtual environment, compiles or installs native ML dependencies, builds the vLLM wheel, and transfers the environment to the final image. Runtime behavior is controlled by CLI arguments and environment variables, with V1 execution enabled in the image and CPU execution selected through the build target.

The FastAPI/Uvicorn surface is dynamically assembled from task-specific routers. It supports OpenAI chat/completions/responses, embeddings and pooling, tokenization, reranking/scoring, LoRA management, Anthropic-compatible messages, SageMaker routes, profiling, and speech-to-text routes. Analyzer extraction found 47 literal HTTP routes; dynamic route construction means this is a bounded inventory rather than proof of the complete runtime surface.

Authentication is conditional: when `--api-key` or `VLLM_API_KEY` is configured, `AuthenticationMiddleware` is added to the ASGI application. TLS is also conditional and configured by certificate/key CLI options. These defaults leave production exposure, certificate validation, and tenant isolation to the platform deployment unless operators explicitly configure the server.
