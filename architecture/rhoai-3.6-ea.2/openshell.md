## Purpose

**Short**: OpenShell provides a policy-governed, private runtime for autonomous AI agents, coordinating isolated sandboxes and controlled provider access.

**Detailed**: The gateway is the control-plane API and authentication boundary. It exposes multiplexed HTTP and gRPC interfaces, persists gateway and sandbox state, and delegates sandbox lifecycle operations to a selected compute driver for Docker, Podman, MicroVM, or Kubernetes. The Rust workspace also supplies the CLI, SDKs, credential drivers, policy verifier, provider registry, middleware/interceptor framework, and sandbox supervisor.

Sandboxes are isolated execution environments with filesystem, process, network, and provider policies. The supervisor is injected into arbitrary workload containers and enforces process and network controls; the gateway mediates SSH/session access, policy updates, credential injection, and lifecycle events. Kubernetes installation is experimental and uses a Helm chart with optional StatefulSet/Deployment, Gateway API GRPCRoute, OpenShift passthrough Route, cert-manager PKI, and optional external database support.

## Architectural Analysis

OpenShell is a layered Rust control plane rather than a Kubernetes operator: the gateway composes compiled-in or externally connected compute and credential drivers, while the selected driver performs environment-specific provisioning. Protocol Buffers define the stable driver, credential, interceptor, middleware, and OpenShell APIs; tonic and Axum share the gateway listener through protocol multiplexing. The separate health and metrics listener options allow operational endpoints to remain isolated from the authenticated control surface.

The security design is defense in depth. Gateway authentication can use OIDC JWT validation or local mTLS, extension credentials are short-lived and rotated, credential storage can be encrypted or delegated to Kubernetes Secrets/Vault, and sandbox egress is filtered at L7 with policy-bound credentials. The Helm chart adds a NetworkPolicy limiting sandbox SSH ingress to the gateway. Important deployment risks are configuration-dependent: TLS can be disabled, extension authentication can be explicitly opted out for trusted-network development, and multi-replica operation requires external database coordination because the default SQLite state is per pod.
