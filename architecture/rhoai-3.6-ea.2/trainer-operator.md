## Purpose

**Short**: Reconciles the platform `Trainer` resource and deploys/configures Kubeflow Trainer v2 resources.

**Detailed**: The operator watches the cluster-scoped `components.platform.opendatahub.io/v1alpha1` `Trainer` resource. It checks platform dependencies, ensures the configured applications namespace exists, renders bundled Kubeflow Trainer manifests and runtime definitions with image overrides, applies them using server-side apply, and reports component/platform release state and conditions.

The container embeds three manifest template sets: the Trainer controller installation, `ClusterTrainingRuntime` definitions, and OpenShift ImageStreams. On OpenShift, ImageStreams are included; on other Kubernetes distributions, only the Trainer and runtime sets are rendered. Cleanup uses label-based discovery and a finalizer, with explicit handling for upstream Trainer resources whose finalizers or cluster scope prevent ordinary owner-reference garbage collection.

## Architectural Analysis

This is a cluster-installed control-plane operator with a platform-facing component CR as its lifecycle boundary and a separately rendered Kubeflow Trainer control plane as its operand. The `Trainer` CR selects the operand namespace through `spec.appNamespace`, while the operator's informer cache can be narrowed to `APPLICATIONS_NAMESPACE`; this reduces cached workload scope but does not turn the cluster-scoped API into a namespaced API.

Manifest rendering is deliberately runtime-driven: image parameters are overlaid into copied writable templates, then applied in dependency/order-aware phases. This supports distribution-specific resources and release/image overrides, but makes the embedded template set and parameter maps part of the operator's supply-chain and upgrade surface. The operator has broad cluster permissions because it provisions CRDs, RBAC, webhooks, monitoring resources, namespaces, workloads, Trainer resources, and OpenShift image resources.
