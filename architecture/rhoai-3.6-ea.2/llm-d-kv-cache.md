## Purpose

**Short**: Provides KV-cache indexing, event ingestion, and scoring primitives for KV-cache-aware routing of vLLM inference workloads.

**Detailed**: The repository contains Go libraries for representing KV blocks, converting prompts to KV-block keys, indexing block locality, and consuming KV-cache events emitted by vLLM. The indexer supports in-memory and Redis/Valkey-backed indexes and exposes scoring operations that allow an inference scheduler to prefer pods with reusable prompt prefixes.

The repository also provides examples for an online HTTP scorer, a gRPC indexer service, and Kubernetes Pod discovery. The Pod reconciler watches ready, label-selected vLLM Pods and creates a ZMQ subscriber for each Pod's KV-event socket. A Helm chart deploys a vLLM workload, KV-cache manager, optional external tokenizer sidecar, optional Redis lookup server, and an optional Hugging Face token Secret.

## Architectural Analysis

This is primarily a reusable Go library and reference implementation rather than a conventional platform operator. Its data plane combines event-driven ingestion over ZeroMQ with prefix scoring over an index; the index can be local or externalized to Redis/Valkey. Pod discovery is implemented with controller-runtime in an example, but the repository has no CRDs and the analyzer found no complete operator RBAC inventory.

The Helm deployment makes the central KV-cache manager a two-port service: TCP/5557 for ZMQ events and TCP/8080 for HTTP. The vLLM workload publishes events to the manager and can optionally use LMCache plus Redis for lookup. The deployment defaults to a single replica and has no visible readiness probe for the manager in the checked-in template, so availability and restart behavior should be treated as deployment concerns for consumers.

Security evidence is mixed: Redis URLs support TLS schemes, but the OTLP exporter is explicitly configured with insecure gRPC transport by default and the gRPC example does not configure TLS credentials. The container uses a UBI9 runtime image and a non-root UID, but no strict-FIPS build flags or hermetic RPM lock files were found in this checkout.
