## Purpose

**Short**: ai4rag optimizes retrieval-augmented-generation templates into RAG Patterns by evaluating configurable model, chunking, retrieval, and vector-store parameters.

**Detailed**: The package accepts Docling documents, benchmark questions/answers, an `AI4RAGSearchSpace`, optimizer settings, evaluators, and a vector-store configuration. `AI4RAGExperiment` orchestrates indexing, retrieval, generation, evaluation, and hyperparameter optimization, returning experiment results and an initialized RAG Pattern.

The model layer is provider-agnostic. Foundation-model and embedding adapters use the OpenAI Python SDK, so the same client can target OpenAI-compatible endpoints including OpenShift AI MaaS, vLLM, TGI, or Ollama. Storage is selected through a configuration discriminator and supports remote Milvus, embedded Milvus Lite, or PostgreSQL/pgvector. S3-compatible discovery and download are optional integrations for document ingestion.

## Architectural Analysis

ai4rag is an in-process orchestration and optimization library, not an independently served API. Its core pipeline composes document chunkers, embedding models, vector stores, retrievers, RAG templates, evaluators, and optimizers behind base interfaces. `SimpleRAG` enriches a user query with retrieved context before calling the configured foundation model; `AI4RAGExperiment` evaluates candidate parameter combinations and emits results through an event-handler interface.

The principal deployment choice is the vector-store backend. Milvus Lite keeps data in a local file for development and small workloads; remote Milvus uses a URL and optional token/CA certificate; PostgreSQL uses an asyncpg pool and pgvector extension. The package deliberately validates Milvus URI schemes and creates storage collections/tables lazily. This makes the library portable but leaves availability, credentials, network policy, and lifecycle management to the consuming notebook, service, or platform workload.
