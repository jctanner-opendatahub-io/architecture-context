## Purpose

**Short**: Automatic and optimized RAG (Retrieval-Augmented Generation) pattern generator that optimizes LLM and vector database parameters.

**Detailed**: AI4RAG is a Python library that serves as an optimization engine for RAG templates. It accepts RAG templates and a search space definition, then applies hyperparameter optimization (HPO) to discover parameter configurations that maximize RAG evaluation metrics. The component is provider-agnostic—it works with any OpenAI-compatible LLM endpoint (hosted APIs, self-managed servers like vLLM/Ollama, or OpenShift AI Models-as-a-Service), and supports multiple vector stores (Chroma, Milvus, PostgreSQL/pgvector). It integrates into data science and ML workflows as a library, not as a standalone service; users import it to run experiments within their Python environments.

## Architectural Analysis

AI4RAG follows a layered Python library architecture organized into functional domains: **core/** (experiment orchestration and HPO optimization), **rag/** (RAG templates, embeddings, retrieval), **evaluator/** (metric computation and RAG quality assessment), **search_space/** (search space definition and constraints), and **utils/** (clients for external services, data utilities, assets). The component is entirely Python-based with no Kubernetes manifests, CRDs, services, or ingress routes—it is consumed as a runtime library dependency, not deployed as a microservice.

The core execution path flows through `AI4RAGExperiment`, which accepts documents, embedding/foundation models, a vector store, and an optimizer, then runs iterative RAG evaluations. The optimizer (GAM-based or random search) adjusts RAG parameters across chunking strategies, retrieval configurations, and prompt tuning, and `UnitxtEvaluator` and `RAGMetric` compute quality metrics. Environment-backed secrets (credentials for vector stores, AWS S3, MaaS tokens) are provisioned at runtime; no persistent secrets management is built into the library.

Integration with external systems is entirely client-side: OpenAI SDK for LLM access, boto3 for AWS S3, specialized clients for Milvus (`pymilvus`) and PostgreSQL (`psycopg`), and Docling for document parsing. No webhook registration, dynamic cluster communication, or operator machinery exists. The library targets Python 3.12–3.13 and carefully manages dependency versions (e.g., `pandas==2.2.*`, `pydantic==2.11.*`) for reproducibility.
