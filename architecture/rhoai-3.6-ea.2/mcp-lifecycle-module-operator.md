## Purpose

**Short**: A Kubernetes operator that manages the lifecycle of the MCP Lifecycle Operator as a module within the RHOAI platform.

**Detailed**: The MCP Lifecycle Module Operator implements the OpenDataHub modular operator pattern, where the ODH platform operator creates a `MCPLifecycleOperator` custom resource (CR), and this module operator reconciles it by deploying and managing the MCP Lifecycle Operator as an operand. The module operator monitors the CR's `managementState` and orchestrates deployment of the operand via Server-Side Apply (SSA) with kustomize-rendered manifests, enforces TLS configuration from the cluster's APIServer profile, and reports readiness through standard Kubernetes conditions. The operand itself manages `MCPServer` resources that define Model Context Protocol (MCP) server endpoints.

## Architectural Analysis

This module operator exemplifies the ODH modular pattern: the platform operator injects environment variables (`SYSTEM_NAMESPACE`, `OPERATOR_VERSION`, `RELATED_IMAGE_ODH_MCP_LIFECYCLE_OPERATOR_IMAGE`) to configure the module operator's behavior at runtime. The operator uses Server-Side Apply (SSA) with the `odh-deployer` library for idempotent, declarative resource application. TLS configuration is dynamically fetched from the cluster's OpenShift `APIServer` CR and passed to operand manifests; on non-OpenShift clusters or when the APIServer resource is unavailable, the operator defaults to hardened intermediate-level TLS profiles.

The reconciliation loop is single-threaded and namespace-scoped to the module's deployment namespace, with cache filtering to avoid listing cluster-wide ClusterRole/ClusterRoleBinding/CRD objects. Garbage collection is driven by the `platform.opendatahub.io/part-of` label: resources managed by this operator are labeled with this value set to the service name (`mcplifecycleoperator`), and stale resources without matching desired manifests are collected and deleted. The operator enforces a CR naming convention via validation rules—only a CR named `default` is permitted—simplifying multi-tenancy: a single operator instance manages a single logical deployment in a single namespace.

Security posture is hardened: the operator runs non-root in a read-only filesystem with minimal capabilities, uses `GOEXPERIMENT=strictfipsruntime` and CGO_ENABLED=1 for FIPS compliance, and delegates authorization to kube-rbac-proxy sidecars and Kubernetes RBAC. No custom secrets handling is performed—the operator only reads and lists Kubernetes secrets to support the operand's bootstrap. TLS is always negotiated with the APIServer before deployment, enforcing consistency across the cluster.
