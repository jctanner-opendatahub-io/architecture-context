## Purpose

**Short**: Praxis AI is a Rust-based AI gateway layer that classifies, transforms, secures, and routes provider-native AI traffic.

**Detailed**: The repository extends the Praxis proxy with AI provider API types, protocol translation, routing filters, prompt enrichment, guardrails, credential injection, token metering, response persistence, and agentic MCP/A2A brokering. The `praxis-ai` binary loads YAML configuration, builds filter pipelines, registers HTTP/TCP protocols, and delegates listener operation to the Praxis/Pingora runtime.

The repository is a reusable server and filter workspace rather than a Kubernetes operator. It supplies a container image and runtime configuration, while Kubernetes Services, Routes, RBAC, and tenant deployment policy are expected to be supplied by a consuming deployment repository.

## Architectural Analysis

Praxis AI separates the stable Praxis networking/runtime layer from rapidly changing AI-specific filters. At startup, the server creates a shared sub-request client, registers built-in and optional filters, resolves a pipeline per configured listener, starts health tracking for configured upstream clusters, and registers admin endpoints. A file watcher can reload pipelines and configuration when an explicit or local `praxis.yaml` is present; listener topology changes require restart.

The primary data plane is protocol- and configuration-driven: client requests enter a listener, pass through ordered filters, and are routed to provider or service backends. Optional integrations include Envoy/llm-d `ext_proc` over a streaming gRPC client and external HTTP callouts. Credential injection deliberately removes caller authorization and inserts a selected bearer token, while sensitive configuration fields are redacted from dumps.

The analyzed checkout contains no Kubernetes manifests or operator objects. The `Containerfile` is a multi-stage Alpine build, statically linking the Rust binary against musl/OpenSSL and running it as a non-root user. This is operationally portable but does not itself establish RHOAI ingress, RBAC, network isolation, or FIPS compliance.
