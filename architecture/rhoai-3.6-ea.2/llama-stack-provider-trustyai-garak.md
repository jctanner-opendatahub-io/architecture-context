## Purpose

**Short**: Provides an eval-hub FrameworkAdapter that runs NVIDIA Garak LLM red-team scans and returns structured vulnerability results.

**Detailed**: The package integrates Garak with the RHOAI eval-hub evaluation platform. In simple mode, an eval-hub Kubernetes Job reads a mounted JobSpec, resolves a benchmark profile, runs Garak as a local subprocess, parses JSONL output, optionally converts it to AVID format, and reports `EvaluationResult` values through eval-hub callbacks.

In KFP mode, the adapter submits a Kubeflow Pipeline, whose components validate configuration, resolve a taxonomy, optionally generate synthetic data, normalize prompts, run Garak, and write results and metrics. Pipeline artifacts and reports are exchanged through S3-compatible storage using Data Connection credentials. The `intents` benchmark is the principal multi-step path and supports judge, attacker, evaluator, target, and SDG model roles.

## Architectural Analysis

This is a library and containerized batch adapter rather than an independently exposed service. Its primary control-plane boundary is the eval-hub JobSpec and callback contract; its data-plane work is the Garak subprocess and the optional KFP/S3 workflow. The single package therefore has two operational topologies while retaining one default container entrypoint.

Configuration is layered: benchmark profiles are deep-merged with JobSpec overrides, then model and credential overlays are applied. API keys are resolved from role-specific environment variables, mounted model-auth files, eval-hub secret access, and finally a dummy fallback for local endpoints. The code redacts API keys before configuration is uploaded or persisted for result processing.

The analyzer found no repository-owned Kubernetes manifests, CRDs, Services, RBAC objects, or inbound HTTP/gRPC registrations. Kubernetes access is nevertheless used at runtime in KFP/S3 credential and image-resolution paths, so the deploying eval-hub/KFP workload must supply the corresponding service-account permissions and secrets. The Konflux build installs Python dependencies from a generated requirements file and also installs Garak from a Git URL in the legacy Containerfile; no OS/package lock or Hermeto metadata was found.
