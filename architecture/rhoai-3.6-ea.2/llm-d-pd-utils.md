## Purpose

**Short**: Provides llm-d operational skills, GPU topology and network diagnostics, and NIXL/UCX data-transfer benchmarks for inference pods.

**Detailed**: The repository packages operational workflows for inspecting llm-d model-serving pods before startup and for measuring GPU topology, RDMA/RoCE, TCP, NCCL/RCCL, iperf3, perftest, and NIXL performance. Its preflight skill can collect environment, GPU, CPU, and PCI data and, in pause mode, hold vLLM startup behind a small HTTP server until an operator calls `/exit` (`README.md:3-20`; `skills/llm-d-preflight-checks/scripts/llm-d-preflight-checks.py:5-22`).

It also supplies direct Pod manifests for a NIXL client/server pair and a NodePort service, plus scripts that run UCX or NIXL transfers over TCP or RoCE. The repository is a test and diagnostics companion for llm-d rather than a long-running platform controller; deployment ownership, authentication, and tenant isolation are largely delegated to the consuming Kubernetes/OpenShift environment.

## Architectural Analysis

The component is an operator-facing test harness with two layers. Python skills run inside or against existing inference pods to inspect hardware and execute performance tests, while shell scripts build/install GPU-aware native dependencies and create short-lived test Pods. The NIXL benchmark uses PyTorch tensors, NIXL agents, and ZeroMQ PAIR sockets for control-plane metadata exchange; UCX provides the data-plane transport and can select TCP or RDMA/RoCE (`benchmarks/benchmark.py:1-18`, `:56-70`, `:93-165`; `benchmarks/benchmark_deployment.sh:40-112`).

The supplied manifests are deliberately minimal and use direct `Pod` objects rather than Deployments. The server exposes a `NodePort` on 5555/30002, while RoCE variants attach a secondary Multus network and add `IPC_LOCK` with GPU, CPU, memory, and `nvidia.com/roce_gdr` resource requests/limits (`deployment/nixl_server.yaml:1-45`; `deployment/nixl_server_roce.yaml:1-43`). This is useful for deterministic benchmarking but leaves availability, rolling replacement, network policy, and access control outside the repository.

Build reproducibility and product security are notable risks. The image is based on mutable NVIDIA CUDA Ubuntu tags, downloads source archives and external packages during the build, has no repository lock files, and installs Python packages with an unconstrained `pip3 install`. It is not an AIPCC/RHEL base image and contains no Konflux-specific Dockerfile or FIPS build signal. The image also installs `libssl-dev`, but no source-level TLS configuration or cryptographic protocol enforcement was found.
