## Purpose

**Short**: Processes AI Gateway inference requests and reconciles provider/model resources into routable Gateway API resources.

**Detailed**: The component embeds the llm-d inference payload processor and exposes an Envoy External Processing gRPC server. Configured plugins can extract model information, select or resolve providers, translate API formats, enforce streaming usage, inject provider credentials, and mutate request or response headers and bodies.

It also runs controller-runtime reconcilers for `ExternalProvider` and `ExternalModel` resources. Providers become namespace-local external services plus Istio `ServiceEntry` and `DestinationRule` resources; models become Gateway API `HTTPRoute` resources that reference the configured RHOAI Gateway. Provider changes enqueue dependent models, allowing routes to be refreshed as provider configuration changes.

## Architectural Analysis

This is a combined control-plane and data-plane process. The controller-runtime manager owns Kubernetes watches and cache behavior, while the same process hosts the ext-proc and health gRPC servers. The data plane is inserted into an Envoy Gateway request path and uses a configurable plugin chain, so routing and credential injection are driven by Kubernetes custom resources and plugin configuration rather than by a separate application API.

The default Helm configuration enables multi-namespace operation. That mode requires a ClusterRole because the secret informer and CRD watches span namespaces; the chart provides a namespace-scoped Role alternative. Secret access is narrowed in application code with the `inference.llm-d.ai/ipp-managed: "true"` label selector, but Kubernetes RBAC still grants broad read access in multi-namespace mode. The component therefore depends on namespace and RBAC policy for its primary tenancy boundary.

The provider reconciler creates external DNS-backed service abstractions and Istio resources, while the model reconciler creates HTTPRoutes attached to a configured Gateway. This makes the Helm release namespace and Gateway namespace operationally significant: the chart documentation requires the release to be installed in the Gateway namespace for Istio EnvoyFilter target references, and the controller uses explicit Gateway name/namespace configuration for route parent references.
