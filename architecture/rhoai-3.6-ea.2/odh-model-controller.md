## Purpose

**Short**: Reconciles KServe model-serving resources and exposes platform model-serving discovery and samples.

**Detailed**: The component is a controller-runtime operator for OpenShift AI model serving. It watches KServe `InferenceService`, `InferenceGraph`, `LLMInferenceService`, `ServingRuntime`, Gateway API, Kubernetes workload, configuration, and secret resources, then creates or updates serving workloads, routes, authorization policies, monitoring resources, RBAC, and tenant-scoped supporting objects.

It also owns the namespaced NVIDIA NIM `Account` API and its validation lifecycle. A separate `model-serving-api` process discovers labeled Gateway resources, serves gateway references and embedded LLM-d samples, and exposes TLS health, readiness, and metrics endpoints. The controller manager uses leader election and admission webhooks for pod and serving-resource mutation/validation.

## Architectural Analysis

This is a dual-workload design: the manager is the reconciliation and admission plane, while `model-serving-api` is a read-oriented HTTPS API. KServe and Gateway API resources are the primary integration contract; the controller translates those resources into per-namespace serving infrastructure, including Services, ServiceAccounts, NetworkPolicies, Routes, HTTPRoutes, EnvoyFilters, RBAC, KEDA authentication, and Prometheus objects.

The RHOAI path supports both current Gateway API traffic and an optional OpenShift Route path. Gateway discovery is authorization-aware through Kubernetes subject-access review, while user-defined LLM authorization is represented by Kuadrant `AuthPolicy`. The analyzer confirms no static ingress route inventory, so dynamically reconciled HTTPRoute/Route behavior remains source-derived rather than manifest-derived.
