## Purpose

**Short**: Maintains additional, digest-pinned RHOAI container image references for disconnected mirroring when those images are not referenced directly by platform manifests.

**Detailed**: This repository is a release-support catalog rather than a deployable application. Its single YAML document groups 59 container image digests under `additional-images` for inclusion in disconnected environments. The catalog covers Ray and FMS tuning images, training runtime images, notebook/workbench images, pipeline runtime images, and deprecated notebook image generations.

The image references are pinned by SHA-256 digest and include both `quay.io/modh` and `registry.redhat.io/rhoai` sources. Comments associate groups with RHOAI release generations and Red Hat issue identifiers. Consumers are expected to use the catalog during image mirroring; the repository itself creates no Kubernetes workloads, services, APIs, or runtime connections.

## Architectural Analysis

This is an inventory boundary in the RHOAI supply chain. It preserves images that may otherwise be omitted from disconnected mirroring because they are not discoverable through currently rendered manifests. The digest pins make the catalog reproducible at the reference level, while the release and deprecation comments provide human-maintained lifecycle context.

The repository has no build recipe or executable source. Consequently, image contents, base images, accelerator compatibility beyond the image names, runtime ports, FIPS posture, and image-level vulnerabilities cannot be verified from this checkout. The catalog also mixes current and deprecated image generations, so consumers need release-aware filtering rather than treating every entry as an active workload image.
