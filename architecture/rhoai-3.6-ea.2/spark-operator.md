## Purpose

**Short**: Runs Apache Spark applications on Kubernetes from declarative Spark custom resources.

**Detailed**: The operator reconciles `SparkApplication`, `ScheduledSparkApplication`, and `SparkConnect` resources, submits and monitors Spark driver and executor pods, supports retries/restarts and scheduling, and exports application metrics. It also provides mutating and validating admission webhooks for Spark resources and pods.

The RHOAI module controller manages installation and lifecycle of the workload operator from the cluster-scoped `SparkOperator` component resource. It owns the deployed manifests, RBAC, webhook configurations, deployments, and related resources. Workload CRs are namespaced, while the module configuration is cluster-scoped.

## Architectural Analysis

This is a two-plane operator. The workload controller watches Spark CRs and their pods/services/configuration, while a separate module controller packages and manages the workload operator installation. The controller deployment is configured for all namespaces by default (`--namespaces=`), with optional explicit namespace lists or namespace-label selection; this makes Kubernetes RBAC and namespace policy central to tenant isolation.

Admission is a fail-closed boundary: mutating and validating webhooks handle Spark resources and pod creation, and webhook certificates are stored in a named Kubernetes Secret. The operator exposes health/readiness endpoints and metrics internally, but no external ingress route is present. The release Dockerfiles use digest-pinned UBI/AIPCC bases and strict-FIPS Go build settings; application TLS uses Go crypto and generated RSA/X.509 webhook certificates, with no custom cipher-suite or minimum-version policy established in the inspected code.

|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Namespace-scoped workload RBAC plus cluster controller identity | Kubernetes | Controller is cluster-capable by default; permissions must be deliberately reduced/configured. |
| Data storage | No operator-owned shared database; Spark workload data is delegated to Spark pods | Kubernetes/Spark | Storage isolation is outside this component. |
| Network traffic | Module watches/owns NetworkPolicy resources | Kubernetes | No complete default-deny policy was established from the baseline. |
| Compute & resources | ResourceQuota is read by validation; PDB and scheduling controls supported | Kubernetes/operator | Fairness and quotas depend on per-namespace platform configuration. |
| Configuration & secrets | Namespaced Spark resources and webhook Secret | Kubernetes | Webhook certificate Secret is shared by the webhook deployment, not per tenant. |
| API scoping | Namespace-scoped CRDs with explicit namespace list/selector support | Kubernetes/operator | Empty namespace configuration watches all namespaces. |
