## Purpose

**Short**: A GPU-free, configurable vLLM-compatible inference simulator for testing clients, schedulers, routing, KV-cache behavior, and observability.

**Detailed**: The simulator exposes OpenAI-compatible HTTP APIs and a vLLM-compatible gRPC engine interface while modeling token generation, time-to-first-token, inter-token latency, queueing, failures, LoRA lifecycle, and Prometheus metrics. Echo and random response modes allow deterministic infrastructure testing without loading a production model.

It can use a built-in or SQLite-backed response dataset, optionally delegates tokenization to a local vLLM render sidecar, and publishes KV-cache events through the llm-d-router library and ZeroMQ. Kubernetes examples include a standalone simulator, KV-cache deployment, prefill/decode disaggregation, and a separate Python ZMQ listener.

## Architectural Analysis

The primary runtime is a single non-root, statically linked Go container. Its communication layer multiplexes gRPC over HTTP/2 and HTTP over one listener using cmux; the normal Kubernetes deployment exposes the listener on TCP 8000 through a NodePort Service. The optional vLLM render container is a native sidecar on localhost:8082 and is readiness-gated before simulator use.

The component is intentionally a test data plane rather than a control-plane operator: it creates no Kubernetes API objects at runtime, has no CRDs or RBAC, and relies on deployment configuration and the surrounding platform for access control. Its broad inference and administration endpoints therefore require network isolation or an authenticated front door when deployed outside a trusted test environment.

The repository also contains experimental deployment topologies for KV-cache and prefill/decode testing. These manifests introduce additional services and routing-sidecar dependencies, but they are separate examples rather than one unified production deployment.
