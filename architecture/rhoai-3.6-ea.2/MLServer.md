## Purpose

**Short**: MLServer is a Python model-serving runtime that exposes KServe v2 REST and gRPC APIs for loading and invoking multiple ML model frameworks.

**Detailed**: MLServer hosts a multi-model registry and dynamically selects model implementations for runtimes including ONNX, scikit-learn, XGBoost, LightGBM, MLflow, HuggingFace, Alibi, CatBoost, and Spark MLlib. Models are loaded from a configurable repository, may be loaded at startup or through the repository API, and can be served through synchronous or streaming inference.

The process starts REST, gRPC, and optional Prometheus metrics servers together. Optional parallel inference workers, adaptive batching, Kafka inference, OpenTelemetry tracing, gzip, CORS, and prediction caching are controlled through `MLSERVER_*` settings. In RHOAI, the serving pod and authentication boundary are supplied by KServe/platform deployment configuration rather than this repository.

## Architectural Analysis

MLServer is a protocol-adapter and runtime-plugin service. A shared data plane and model registry feed both the FastAPI REST layer and the AsyncIO gRPC layer; model load, reload, and unload callbacks update dynamically installed REST handlers and optional inference pools. The repository includes no Kubernetes deployment manifests, Services, RBAC, or Routes, so deployment topology and network policy are external concerns.

The Konflux images deliberately generate `/etc/mlserver/trusted-runtimes.json` from build arguments. When that file exists, runtime import paths are allow-listed in production mode; when absent, development mode permits custom implementations. This creates a useful supply-chain boundary around dynamically loaded model code, but the application gRPC listener and OTLP exporter are not TLS-configured in the inspected source and require platform/network controls where encryption is needed.
