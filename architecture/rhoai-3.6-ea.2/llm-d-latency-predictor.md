## Purpose

**Short**: Provides online machine-learning prediction and continuous training for llm-d time-to-first-token (TTFT) and time-per-output-token (TPOT) latency.

**Detailed**: The component is a Python/FastAPI service split into a prediction server and a training server. The prediction server loads locally cached model artifacts, accepts latency-feature requests, and returns TTFT/TPOT estimates and uncertainty. The training server accepts observed request samples, trains Bayesian Ridge, XGBoost, or LightGBM models, and persists model and scaler artifacts.

The prediction deployment periodically synchronizes model artifacts from the internal training service over HTTP. Training data and model state are maintained in memory and serialized with joblib; the training deployment can use a persistent volume in the GKE overlay, while prediction replicas use per-pod `emptyDir` storage. Kubernetes health/readiness probes gate traffic until prediction models are available.

## Architectural Analysis

This is a horizontally scalable prediction tier paired with a single training leader. The base manifests configure ten prediction replicas and one training replica. Prediction instances are stateless with respect to durable model storage: they download models from training and maintain local copies, which reduces shared-volume coupling but creates a synchronization window controlled by `MODEL_SYNC_INTERVAL_SEC` (10 seconds by default).

The training server exposes both operational and model-management endpoints in the same unauthenticated FastAPI surface as data ingestion and prediction. The default base deployment is internal ClusterIP-only, but the GKE overlay adds LoadBalancer services for prediction and training. No application authentication, Kubernetes RBAC, ingress policy, or TLS configuration was detected, so external exposure requires platform-level controls and should be treated as a deployment risk.
