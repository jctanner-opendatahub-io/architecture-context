## Purpose

**Short**: Kubeflow Trainer provides Kubernetes-native APIs and controllers for distributed AI training jobs and training runtimes.

**Detailed**: The controller manager reconciles `TrainJob`, `TrainingRuntime`, and `ClusterTrainingRuntime` resources into distributed workloads. It supports framework plugins including PyTorch, JAX, XGBoost, DeepSpeed, MLX, MPI, Flux, JobSet, Volcano, and co-scheduling integrations.

The component also supplies admission validation/defaulting, status reporting, runtime configuration, and optional data-cache and initializer images. Training jobs are namespace-scoped while reusable cluster training runtimes are cluster-scoped, allowing platform administrators to publish runtimes for namespace users.

## Architectural Analysis

Trainer is a controller-runtime-based control-plane component. A single manager Deployment combines reconciliation, admission webhooks, metrics, health probes, and a TLS status server behind one ClusterIP Service. Runtime plugins translate a TrainJob into framework-specific Kubernetes resources and watch selected dependent resources such as JobSet, PodGroup, ConfigMap, and Secret.

The RHOAI overlay adds release-specific configuration, metrics, TLS-profile RBAC, and the `opendatahub` deployment namespace. The design delegates user authorization and tenant boundaries to Kubernetes RBAC and namespace scoping; the manager itself necessarily has broad cluster-level permissions to reconcile workloads and shared runtime resources.
