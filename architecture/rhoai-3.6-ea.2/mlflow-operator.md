## Purpose

**Short**: Manages the lifecycle, routing, authorization, storage, and monitoring resources for MLflow instances on Kubernetes.

**Detailed**: The operator reconciles cluster-scoped `MLflow` resources and renders a Helm chart into a target application namespace. The rendered workload provides an MLflow tracking server, optionally a dedicated artifact server, optional garbage-collection and trace-archival jobs, Services, PVCs, NetworkPolicies, ServiceAccounts, RBAC, and ServiceMonitors.

The operator also supports a cluster-scoped `MLflowOperator` singleton for projected platform configuration and a namespace-scoped `MLflowConfig` singleton for per-workspace artifact storage overrides. A namespace RBAC controller can create group-based RoleBindings when enabled. Gateway API routes are created conditionally when the `HTTPRoute` CRD is available.

## Architectural Analysis

This is a controller-runtime operator with a cluster-wide control plane and namespace-scoped data-plane resources. The `MLflow` API is cluster-scoped so one operator can manage instances, while the generated MLflow server is placed in the configured applications namespace. Shared MLflow server RBAC is cluster-scoped and intentionally permits cross-namespace discovery because the MLflow service serves workspaces across namespaces; user authorization is delegated to MLflow's Kubernetes self-subject access review mode.

The operator uses Helm rendering as its resource-construction boundary. Reconciliation is event-driven: the primary controller owns the MLflow deployment resources and watches referenced Secrets, selected ConfigMaps, shared RBAC, and optional Gateway API and Prometheus resources. Gateway API availability is discovered at runtime; standard tracking routes are skipped when unavailable, while the dedicated artifact-server mode rejects reconciliation because its route is required.

| API scoping | `MLflowConfig` is namespaced; `MLflow` and operator singleton are cluster-scoped; controller watches cluster-wide where required | Kubernetes API and controller-runtime | Cluster-scoped MLflow API and shared RBAC expand blast radius; application auth must remain correct. |
