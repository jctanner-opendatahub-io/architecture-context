## Purpose

**Short**: Reconciles an `LLMBatchGateway` custom resource into a complete, namespace-scoped LLM-D batch gateway deployment.

**Detailed**: The operator watches `batch.llm-d.ai/v1alpha1` `LLMBatchGateway` resources and maps their specification to Helm values. It renders the embedded batch-gateway and async-processor charts, sets owner references, and applies the resulting Kubernetes resources with server-side apply. It reports component and overall readiness through status conditions.

The managed workload provides an HTTP batch API, request processing, garbage collection, optional asynchronous processing, database-backed job state, and filesystem- or S3-compatible file storage. The operator also manages optional HTTPRoute exposure, TLS certificates, Prometheus monitoring, Grafana dashboards, and credential-secret synchronization. It resolves the OpenShift API-server TLS profile for its own metrics endpoint and injects the profile into rendered chart values.

## Architectural Analysis

This is a cluster-installed control-plane operator with a namespaced tenant-facing API. A single controller manager uses cluster-scoped RBAC to reconcile namespaced `LLMBatchGateway` objects, while generated data-plane resources remain in each CR namespace. Helm charts are shipped or prefetched into the operator image and rendered at runtime, so the operator is both the lifecycle controller and the chart execution boundary.

The design deliberately separates platform image selection from the CR: four component image references are supplied through deployment environment variables and are required before reconciliation can start. Chart configuration supports Gateway API HTTPRoutes and cert-manager certificates, but the default chart values leave application TLS and external HTTPRoute exposure disabled. The operator's metrics surface is HTTPS by default and obtains its service certificate through the OpenShift service-ca annotation.

The broad ClusterRole is a material trust boundary: the operator can create or modify workloads, secrets, RBAC, routes, monitoring objects, and certificates across namespaces. Secret references can cross namespaces only when a `ReferenceGrant` permits them; the controller copies the source secret into the target namespace under a managed name. S3 isolation is configured by key prefixes in a shared bucket, making correct prefix configuration an application-level responsibility.
