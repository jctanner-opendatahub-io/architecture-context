## Purpose

**Short**: `odh-cli` is a Go kubectl-style CLI for inspecting, validating, diagnosing, migrating, and operating RHOAI deployments on Kubernetes.

**Detailed**: The CLI provides Cobra commands for component discovery and mutation, dependency inspection, linting, status and event inspection, logs, backups, migrations, diagnosis, and API metadata. It uses Kubernetes client-go and cli-runtime configuration, accepting kubeconfig, server, token, certificate, context, and namespace options.

The binary is primarily a local or containerized command-line tool and does not install a Kubernetes workload. It can additionally expose its command set through an MCP server, using stdio by default or an optional loopback SSE listener. Commands execute with the caller's Kubernetes credentials and permissions; authorization checks are performed against the Kubernetes API for operations that require pre-flight permission validation.

## Architectural Analysis

`odh-cli` is intentionally a client-side control-plane utility rather than a continuously running platform component. This keeps deployment and tenancy responsibilities in Kubernetes and makes the caller's identity the primary security boundary. The broad command surface is assembled in `cmd/main.go`, while domain-specific operations are organized under `pkg/` packages.

The Konflux image is multi-stage, digest-pinned, cross-compilable, and configured for strict Go FIPS runtime behavior. The runtime image includes OpenShift CLI utilities and `jq`, and defaults to `/kubeconfig` for container use. No Kubernetes manifests, controllers, services, or RBAC objects are shipped by the repository.

The main security concern identified in the source is the TrustyAI metrics helper's unconditional `InsecureSkipVerify`, which weakens server identity validation for any URL it calls. The optional MCP SSE mode is also intentionally unauthenticated at the listener layer; loopback binding reduces exposure, but a user should not bind or proxy it externally without an additional authentication and TLS boundary.
