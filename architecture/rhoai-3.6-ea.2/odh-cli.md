## Purpose

**Short**: CLI tool and kubectl plugin for managing, linting, diagnosing, and migrating Red Hat OpenShift AI (RHOAI) deployments on Kubernetes clusters.

**Detailed**: The odh-cli component is a comprehensive command-line interface that provides administrators and operators with tools to manage RHOAI clusters and components. It supports deployment diagnostics, component health checking, migration operations between RHOAI versions, backup/restore functionality, linting and validation of deployments against target versions, and integration with Model Control Protocol (MCP) for agent-based interactions. The tool is distributed as a containerized binary bundled with kubectl and oc utilities, enabling execution in containerized environments via Podman or Docker. It serves as both a standalone CLI invoked directly and as a kubectl plugin accessed via `kubectl odh` commands, providing both interactive and programmatic interfaces for cluster management and troubleshooting.

## Architectural Analysis

The odh-cli is a stateless CLI application designed as a distributed, single-binary tool that runs as a container image or as a standalone kubectl plugin. The architecture demonstrates several key patterns:

**Command Structure**: The CLI uses Cobra framework with a hierarchical command structure encompassing 13 subcommands: `lint`, `migrate`, `backup`, `diagnose`, `status`, `get`, `components`, `deps`, `logs`, `events`, `mcp`, `completion`, `api`, and `version`. This modular design allows independent command packages to be extended without affecting core functionality.

**Kubernetes Integration**: The tool extensively leverages Kubernetes client-go libraries (v0.35.2) with support for multiple authentication methods: kubeconfig files, bearer tokens, client certificates, and OIDC (via k8s.io/cli-runtime/pkg/genericclioptions ConfigFlags). It uses `SelfSubjectAccessReview` API calls (pkg/util/kube/rbac/check.go:60) to perform RBAC pre-flight authorization checks before executing privileged operations, ensuring safe failure when permissions are insufficient.

**Multiple Kubernetes Client Types**: The codebase instantiates discovery clients, dynamic clients, typed clientsets, and OLM-specific clients to interact with both standard Kubernetes APIs and Operator Lifecycle Manager (OLM) APIs for managing ClusterServiceVersion and Subscription lifecycle operations. This multi-client pattern enables querying diverse API surfaces within a single tool.

**Component Ecosystem Knowledge**: The analyzer identified 27+ platform component references spanning kubeflow.org, serving.kserve.io, route.openshift.io, infrastructure.opendatahub.io, and gatewayconfig resource groups. The pkg/lint/checks/components/ directory contains 44 Go files implementing component-specific validation rules for KServe, Dashboard, DataScience Pipelines, TrainingOperator, Ray, Kueue, ModelMesh, LlamaStack, and AIGateway—indicating deep architecture awareness embedded in linting logic.

**FIPS Compliance by Design**: The Dockerfile.konflux enforces FIPS compliance at build time with explicit flags: `GOEXPERIMENT=strictfipsruntime`, `CGO_ENABLED=1`, and `-tags strictfipsruntime`. This ensures the binary dynamically links to system OpenSSL (from UBI9 ose-cli-rhel9 base) rather than using pure-Go crypto, passing Konflux check-payload validation. Application-level TLS uses stdlib crypto/tls, which delegates to OpenSSL when CGO_ENABLED=1.

**MCP Protocol Bridge**: Integration with Model Control Protocol (mark3labs/mcp-go v0.55.1) via `mcp serve` command enables programmatic access from AI agents and tooling. The `pkg/mcp/tools.go` imports opendatahub-operator/pkg/mcptools, exposing diagnostic and operational capabilities as MCP tools—positioning odh-cli as an extensible platform for agent-driven cluster operations.

**Hermetic Supply Chain**: The release branch includes rpms.lock.yaml with SHA256 checksums for multi-arch OS packages (aarch64, ppc64le, x86_64) and go.sum for Go module pinning. Cross-compilation is handled via TARGETOS/TARGETARCH build arguments, enabling reproducible builds across platforms.
