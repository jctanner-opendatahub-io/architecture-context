## Purpose

**Short**: Kubeflow Pipelines provides APIs, UI, workflow orchestration, metadata, caching, and artifact storage for end-to-end machine-learning workflows on Kubernetes.

**Detailed**: The component exposes KFP v1/v2 HTTP and gRPC APIs for pipeline, experiment, run, job, task, artifact, and visualization operations. The API server persists pipeline metadata in MySQL/ML Metadata, stores artifacts in S3-compatible storage, and uses Kubernetes APIs to create and observe workflow resources.

The deployment includes Argo Workflow execution, scheduled-workflow and viewer controllers, a persistence agent, cache server/deployer, metadata writer and Envoy, visualization server, a React UI, and bundled MySQL and SeaweedFS support. RHOAI uses the namespace-scoped `kubeflow` installation pattern with separate service accounts and Roles for each workload.

## Architectural Analysis

This is a distributed control plane rather than a single server: the API server is the user-facing orchestration point, while Argo and KFP controllers reconcile execution and scheduled resources. The persistence agent and metadata services provide asynchronous state synchronization, and the cache server avoids repeating work by observing workflow/pod state. The UI and visualization server are internal ClusterIP services and rely on the API and artifact paths.

The analyzer identifies 14 workloads, 9 services, 2 core CRDs, 27 HTTP routes, and 10 gRPC services. Authentication and dynamic route construction are only partially resolved by static analysis; the gRPC server options and 57 inbound runtime surfaces do not have fully attributable auth facts. The bundled MySQL and SeaweedFS resources are convenient deployment defaults but create shared stateful-service and supply-chain responsibilities for production operators.
