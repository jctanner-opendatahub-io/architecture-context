## Purpose

**Short**: Builds the Red Hat Open Data Hub OGX distribution image, packaging the OGX server, provider dependencies, runtime configuration, and model/data cache.

**Detailed**: This repository is a downstream distribution layer rather than the OGX application source. It generates a RHOAI-branded container image containing the upstream OGX 1.3.1+rhaiv.0 Python runtime, a curated provider configuration, pre-resolved Python dependencies, and model/data artifacts supplied by a separate modelcar image.

The resulting service listens on port 8321 and exposes OGX APIs for responses, messages, batches, inference, tool runtime, vector I/O, files, and file processing. Providers can be local or remote, including OpenAI-compatible inference, vLLM, Bedrock, Vertex AI, Azure, Gemini, Anthropic, Milvus, pgvector, Qdrant, S3, and search providers. PostgreSQL is the default persistent backend for key/value and SQL stores.

## Architectural Analysis

The component is an image assembly and configuration boundary. `Dockerfile.konflux` uses an AIPCC CPU RHEL 9 base, installs a hash-pinned Python lockfile offline through Cachi2/Hermeto-prefetched wheels, and copies model/data artifacts from a ProdSec-scanned modelcar stage. The generated `distribution/config.yaml` removes dependency-only providers from the default runtime configuration while retaining their packages for custom configurations.

At runtime, `entrypoint.sh` resolves mounted secret files, selects either a custom `RUN_CONFIG_PATH`, a named distribution, or the bundled configuration, and invokes `ogx run --insecure`. The `--insecure` argument is an application-runtime concern: provider TLS verification is configurable in the generated configuration, while the repository does not contain the OGX server source needed to verify its HTTP listener or all TLS implementation details. The default local Milvus provider is explicitly incompatible with multi-worker deployments, and shared PostgreSQL/vector backends require deployment-level tenant controls.
