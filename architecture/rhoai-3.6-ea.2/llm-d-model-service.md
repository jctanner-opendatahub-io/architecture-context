## Purpose

**Short**: Reconciles `ModelService` resources into model-serving deployments and Gateway API inference routing resources for llm-d.

**Detailed**: The component is a Go controller-runtime application with a Cobra command line. Its primary API is the namespaced `llm-d.ai/v1alpha1` `ModelService` custom resource. A reconcile reads the resource, interpolates template variables, optionally loads a base configuration from a ConfigMap, merges overrides, creates or updates child resources, and reports observed status.

The generated serving topology can contain prefill and decode workloads, model artifact volumes or credentials, Services, ServiceAccounts, RoleBindings, HTTPRoutes, InferenceModels, and InferencePools. The controller watches those resources and maps changes back to their owning `ModelService`. A separate `generate` command renders equivalent child manifests offline.

## Architectural Analysis

This is a domain controller rather than a request-serving application. Kubernetes is the durable control plane: desired state enters through `ModelService`, while the controller materializes the data-plane resources and maintains status. The CRD supports decoupled prefill/decode configuration, accelerator selection, container overrides, model artifacts from PVC/Hugging Face/OCI sources, and Gateway API parent references.

The controller is intentionally integrated with the Gateway API Inference Extension. It owns routing and inference-extension objects alongside ordinary Kubernetes workloads, so availability depends on those CRDs and their implementing gateway/EPP components. The manager has a secure metrics mode by default and disables HTTP/2 by default, but leader election is disabled in the checked-in deployment arguments; the single-replica deployment therefore has no active failover configuration unless operators override it.
