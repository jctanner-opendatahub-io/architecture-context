## Purpose

**Short**: Provides reusable Kubeflow Pipelines components and pipeline definitions for data processing, AutoML, AutoRAG, model deployment, evaluation, and fine-tuning.

**Detailed**: `kfp-components` is a Python package that packages component functions and complete pipeline definitions for Kubeflow Pipelines. It includes data loaders and processors, AutoML and AutoRAG workflows, fine-tuning workflows, evaluation integrations, model registry operations, and model deployment components.

The repository is not itself a long-running API service or Kubernetes operator. Its components are compiled and executed as KFP tasks, while the packaged Konflux images provide task-specific Python dependencies and generated managed-pipeline assets. Some tasks use the Kubernetes Python client to create or manage KServe resources, and other tasks connect to S3-compatible storage, Hugging Face, Google Cloud Storage, Milvus, LLM endpoints, and KFP services.

## Architectural Analysis

This repository is an orchestration and component-definition layer: KFP supplies the execution boundary, artifact passing, secret injection, and task isolation, while the component code performs data movement, transformation, training, evaluation, and deployment actions. The main Konflux image initializes managed pipelines; separate AutoML and AutoRAG images package heavier or domain-specific dependency sets. The repository also exposes component-level `base_image` and `packages_to_install` declarations, so the final runtime image may be selected by the compiled KFP component rather than by this repository's main container alone.

The deployment component is an important control-plane bridge. It accepts a target namespace and uses namespaced Kubernetes custom-object operations to create, read, patch, and delete KServe `InferenceService` resources, while generating a vLLM `ServingRuntime` configuration and using a PVC-backed model cache. This is application-driven resource management rather than an operator reconciliation loop; authorization and tenant isolation therefore depend heavily on the service account and namespace context of the KFP task.

The strongest identified security concern is the S3 loader's recovery path: after an SSL error it logs a warning and retries with `verify=False`. This preserves availability for incompatible endpoints but permits unauthenticated server certificates and should be treated as an explicit exception requiring controlled endpoint and trust-store policy.
