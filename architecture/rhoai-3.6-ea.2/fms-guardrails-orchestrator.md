## Purpose

**Short**: Provides a unified REST API that orchestrates text generation and content detection services to apply safety guardrails.

**Detailed**: FMS Guardrails Orchestrator is a Rust/axum middleware service for detector-backed safety checks on text, chat, context documents, completions, and generated output. It exposes versioned HTTP endpoints and coordinates configured generation providers (TGIS, caikit-NLP, or optional OpenAI-compatible chat generation), detector services, and chunker services.

The process runs a guardrails listener and a separate health listener. Configuration is loaded from YAML, with command-line/environment overrides for ports, configuration path, TLS certificate paths, and OpenTelemetry export. Requests can stream through SSE or newline-delimited JSON workflows, while detector and chunker concurrency defaults to five requests each (`src/config.rs:34-40`, `src/config.rs:230-235`).

## Architectural Analysis

The component is a single deployable binary with a deliberately split network surface: port 8033 handles guardrails traffic and port 8034 handles unauthenticated liveness and cached dependency information. The guardrails router is assembled conditionally, enabling the OpenAI-compatible completion routes only when an `openai` configuration is present (`src/server/routes.rs:69-110`). This keeps optional integrations out of the active API surface while retaining one process and shared orchestrator state.

The orchestration model is configuration-driven rather than Kubernetes-API-driven. A YAML document names generation, detector, chunker, health-check, and reusable TLS client configurations; the application resolves named TLS profiles and validates service definitions before startup (`src/config.rs:208-309`). Downstream calls can use HTTP or gRPC client implementations and can carry a deliberately allow-listed set of request headers. The optional `X-Forwarded-Access-Token` rewrite turns a trusted forwarded header into an `Authorization: Bearer` header (`src/server/routes.rs:451-479`), so deployment boundaries must ensure only an appropriate authenticated proxy can supply that header.

The source has no in-repository Kubernetes workload, RBAC, Service manifest, ingress, CRD, or controller. The analyzer therefore identifies runtime listener/service facts from Rust source, not a complete deployment topology. Release Dockerfiles build and test the binary, use UBI 9 bases, run as a non-root user, and provide no container healthcheck (`Dockerfile.konflux:1-65`).
