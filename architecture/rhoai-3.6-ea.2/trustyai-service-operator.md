## Purpose

**Short**: Kubernetes operator that deploys and manages TrustyAI, evaluation, guardrails, and language-model evaluation components.

**Detailed**: The operator reconciles TrustyAIService, EvalHub, GuardrailsOrchestrator, LMEvalJob, NemoGuardrails, and TrustyAI platform resources. It creates component workloads, services, service accounts, RBAC, configuration, storage, and status updates from namespaced custom resources.

It also includes a platform module controller for the cluster-scoped `TrustyAI` API, watches KServe InferenceServices and optional monitoring resources, and reads OpenShift APIServer TLS profiles to configure hardened controller webhooks. The EvalHub and TrustyAIService APIs use conversion webhooks to bridge served API versions.

## Architectural Analysis

This is a consolidated, multi-controller Go operator with a separate `trustyai-operator-module` controller-manager image. The main manager enables controllers according to configured services; several controllers create workloads dynamically from templates, including TrustyAI Service deployments fronted by `kube-rbac-proxy`. The operator therefore acts as both a Kubernetes control-plane extension and a workload factory for evaluation and guardrails services.

The deployment surface is broader than the two baseline workloads: controller logic creates namespaced services, routes, Istio resources, secrets, RBAC, PVCs, jobs, and evaluation-related resources conditionally. The analyzer reports dynamic construction limitations, so templated names and some route/service details remain parameterized in this summary.
