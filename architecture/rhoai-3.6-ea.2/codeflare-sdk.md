## Purpose

**Short**: CodeFlare SDK is an intuitive Python client library that simplifies batch resource requesting, access, job submission, and observation for high-performance compute resources in Kubernetes clusters.

**Detailed**: CodeFlare SDK provides developers with an easy-to-use Python interface for managing distributed computing resources in cloud or on-premises Kubernetes environments. The library abstracts the complexity of requesting and managing Ray clusters, handling Kueue-based batch queuing, and executing distributed workloads. It supports multiple authentication methods (OIDC, OpenShift OAuth, kubeconfig, token-based, in-cluster service accounts) through the kube-authkit dependency, allowing seamless integration with both ODH and RHOAI deployments. The SDK enables data scientists and developers to declaratively define cluster configurations, submit jobs, and monitor execution without direct Kubernetes manifest manipulation.

## Architectural Analysis

CodeFlare SDK follows a client library architecture pattern where the primary artifact is a PyPI-distributed Python package consumed by end-user applications. The library is organized into three main functional domains: Ray cluster management (`codeflare_sdk.ray`), Kubernetes-level operations (`codeflare_sdk.common.kubernetes_cluster`), and Kueue queue management (`codeflare_sdk.common.kueue`).

The deployment model distinguishes CodeFlare from operators: it does not run as a pod in the cluster; rather, it is imported and instantiated in user applications (notebooks, scripts, or applications) that communicate with the cluster's Kubernetes API. This makes it a **client-side library** rather than a **cluster-resident service**.

Authentication is delegated to kube-authkit, which supports auto-detection of in-cluster or out-of-cluster credentials. The library exports a `set_api_client()` function allowing users to register custom Kubernetes clients, enabling flexibility in authentication strategies.

The codebase includes test containers (Dockerfile at `images/tests/Dockerfile`) that bundle the SDK, test dependencies, and E2E test harnesses. These containers are not production deployment artifacts; they serve the CI/CD test pipeline and validate cluster integration via RBAC test roles covering Ray and Kueue API access.

| Endpoint | Methods | Auth Mechanism | Enforcement Point | Policy |
|----------|---------|----------------|-------------------|--------|
| Kubernetes API (SDK client) | All | Bearer Token / mTLS | Kubernetes RBAC | Cluster-defined RBAC roles |

| OpenShift OAuth (RHOAI) | POST (token exchange) | OpenShift OAuth Bearer Flow | OpenShift API server | OpenShift RBAC |

**Authentication Strategy**: CodeFlare SDK delegates authentication to kube-authkit, which supports the following flows:
- **Auto-detect**: Tries kubeconfig, then in-cluster service account, then prompts for manual auth
- **OIDC Device Flow**: External OIDC providers with device code entry for CLI/headless environments
- **OpenShift OAuth**: Direct OpenShift OAuth flow (RHOAI-native)
- **Token-based**: Bearer token + API server URL
- **Kubeconfig**: Traditional kubeconfig file (file or environment variable)
- **In-cluster**: ServiceAccount token when running inside a pod

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Delegated to cluster RBAC; CodeFlare respects Kubernetes ServiceAccount or user identity | Kubernetes / kube-authkit | Admin must configure cluster RBAC; SDK applies no isolation |
| Data storage | Delegated to user-configured Ray cluster and storage backends (S3, MinIO, etc.) | Application / User | CodeFlare does not enforce data encryption or access control; depends on end-to-end integration |
| Network traffic | Delegated to cluster NetworkPolicy or Istio AuthorizationPolicy | Kubernetes / Istio | CodeFlare does not define network policies; cluster admin must implement |
| Compute & resources | Ray cluster-enforced (via Kueue and resource requests); CodeFlare submits workloads with resource spec | Kubernetes / Ray / Kueue | CodeFlare defines but does not enforce; cluster-level policies control enforcement |
| Configuration & secrets | Delegated to Kubernetes Secrets and kubeconfig files | Kubernetes | CodeFlare reads secrets referenced in manifests; does not isolate |
| API scoping | Namespace-aware at Kubernetes level; CodeFlare watches only namespaces its ServiceAccount can access | Kubernetes RBAC | Multi-namespace clusters require explicit RBAC per namespace |

Tenant isolation is enforced at the Kubernetes and Ray cluster level by administrators. CodeFlare respects those boundaries but adds no isolation layer of its own.
