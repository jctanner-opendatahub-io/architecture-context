## Purpose

**Short**: CodeFlare SDK is a Python client for requesting Ray compute clusters, submitting Ray jobs, and observing or managing those resources on Kubernetes/OpenShift.

**Detailed**: The SDK gives notebook and application users a high-level interface for creating RayCluster resources, selecting CPU/GPU and other accelerator resources, configuring autoscaling, and waiting for cluster readiness. It renders KubeRay custom resources and applies them through the Kubernetes Python client; KubeRay then owns the actual Ray head and worker pods.

It also exposes RayJob lifecycle operations, including submission, suspension, resubmission, deletion, status, runtime environments, and optional creation of a short-lived managed cluster. Kueue LocalQueue and WorkloadPriorityClass integration adds queue and preemption metadata when those platform services are installed. Authentication is delegated primarily to kube-authkit, with deprecated token and kubeconfig compatibility classes retained.

## Architectural Analysis

This is a control-plane SDK, not a long-running service or containerized workload. Its primary boundary is the Kubernetes API: the process authenticates to a user-selected cluster, constructs `ray.io/v1` resources, and uses dynamic or custom-object clients to create, inspect, patch, and delete them. Runtime data-plane traffic is handled by Ray pods; the SDK discovers cluster endpoints and uses Ray's job submission client where needed.

The design supports both interactive, user-managed clusters and RayJob-managed ephemeral clusters. Configuration is intentionally broad: namespace, resource requests, accelerator mappings, tolerations, volumes, images, autoscaling, GCS fault tolerance, usage statistics, queueing, and TLS verification are all represented in Python configuration objects. The main risks are delegated permissions and cluster policy, plus the legacy `skip_tls` option that can disable certificate verification when explicitly selected.
