## Purpose

**Short**: Grid is a distributed control plane that orchestrates multi-site AI inference routing across Kubernetes clusters, cloud providers, and third-party APIs using SWIM gossip protocol and CRDT state convergence.

**Detailed**: Grid operates as the control plane in a two-tier architecture with Praxis (the data plane gateway). While Praxis handles request routing and proxying, Grid solves the discovery and orchestration problem: figuring out where AI inference models are deployed, which backends are healthy, and which provider should handle the next request.

Grid implements three core mechanics:

1. **Peer Discovery**: Uses the SWIM (Scalable Weakly-consistent Infection-style Membership) gossip protocol to establish mesh membership across multiple Kubernetes clusters and edge sites. Each site runs a Grid operator instance that announces itself and discovers peers.

2. **State Synchronization**: Employs Delta CRDTs (Conflict-free Replicated Data Types) to propagate provider availability and health state across the mesh without central coordination. This enables sites to have eventually-consistent views of all available inference capacity.

3. **Routing Overlay Rendering**: Scores candidate providers (by queue depth, KV cache pressure, or provider-level metrics) and writes a versioned ConfigMap (routing overlay) that each Praxis gateway watches and hot-reloads. Requests never flow through Grid; all routing decisions use pre-computed local overlay files.

Grid integrates tightly with Kubernetes through custom resources (`GridNetwork`, `GridSite`, `InferenceProvider`) and RBAC. The operator watches these CRDs, manages TLS certificates for inter-gateway mTLS communication, handles SWIM encryption, and reconciles provider health via probes.

## Architectural Analysis

Grid is a sophisticated distributed system that decouples the control plane (Grid) from the data plane (Praxis). This separation allows Grid to operate without being in the request path, making it horizontally scalable and resilient to operator failures. The SWIM protocol provides peer discovery without requiring a central coordinator, and Delta CRDTs enable conflict-free state replication across eventually-consistent networks.

**Key architectural patterns:**

- **Process-wide Crypto Provider Isolation**: The operator uses explicit `rustls::crypto::CryptoProvider::install_default()` to select the `ring` provider process-wide (operator/src/main.rs). This is necessary because the operator links multiple crates with different crypto requirements: `hyper-rustls` (via kube client) uses `ring`, and `reqwest` (via rmcp for provider probes) was built with `rustls-no-provider` to avoid conflicting providers. The operator resolves this by installing `ring` explicitly before building clients.

- **Static Type Safety with Rust**: The entire codebase is written in Rust with `unsafe_code = "forbid"` enforced by workspace lints (Cargo.toml:87). All crypto is delegated to vetted dependencies (ring, aes-gcm, x509-parser), eliminating entire classes of memory safety bugs.

- **mTLS Between Gateways**: Grid operators exchange SWIM membership and provider state over mTLS. Each site has a gateway identity backed by X.509 certificates (managed by the `certs` crate via rcgen). SWIM packets can be encrypted with AES-256-GCM; the key is sourced from either an environment variable (`GRID_SWIM_ENCRYPT_KEY`) for testing or a Kubernetes Secret (via `GridNetwork.spec.tls.swimKeyRef`) for production.

- **Operator-Driven Configuration**: The Grid operator is the only writer to routing overlays. It watches `GridNetwork`, `GridSite`, and `InferenceProvider` CRDs, reconciles them against actual cluster state, and writes ConfigMaps that Praxis reads. This keeps the operator as a single source of truth for routing topology.

- **Health Probing and Scoring**: The `InferenceProvider` controller probes backends and feeds health signals into a pluggable scoring engine. The operator applies a site-level scoring strategy (`queueDepth`, `kvCachePressure`, or `noMetrics` for external APIs) before writing the overlay. Request-level load balancing (e.g., prefix affinity for llm-d pods) remains within Praxis or the backend itself.

- **CRDT Convergence Without Coordination**: Delta CRDT types (Last-Write-Wins, OR-Set, G-Counter) are used for distributed spend tracking, provider state, and membership records. No two-phase commit; all state converges eventually as SWIM gossip distributes updates.

**Deployment Characteristics**:
- Current deployment is single-instance (replicas: 1) for the operator Deployment, appropriate for a control plane managing stateless gateways.
- Sidecar (`grid-overlay-sync`) provides fast ConfigMap-to-file delivery for Praxis gateways, reducing watch latency.
- The operator never processes user requests; all routing overhead is borne by Praxis gateways.

**Risk and observability notes:**
- **Crypto provider selection complexity**: Mismatches can cause runtime panics. The workspace documents this via comments on `reqwest` and `rmcp` features.
- **Single operator instance**: Current deployment is not HA. Operator restarts trigger CRDT state re-convergence from peers.
- **No ingress for operator endpoints**: The operator exposes `/healthz` and `/readyz` probes on port 9090 (metrics port) but no public ingress. Routing overlays are delivered via ConfigMaps.

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Service Account RBAC for operator; per-GridNetwork visibility; per-namespace secret references | Kubernetes API Server + operator logic | Operator runs with single SA; cannot enforce different RBAC per tenant. GridNetwork is cluster-scoped, so all clusters see all networks. Per-namespace secret scope provides weak tenant boundary. |
| Data storage | Per-GridNetwork CRDT state (separate LWW/OR-Set/G-Counter instances per network); per-GridNetwork ConfigMaps | operator (CRDT instances keyed by GridNetwork name) | CRDT state is stored in-memory; no persistent backend isolation. If operator crashes, remote CRDT state is re-learned from SWIM peers. |
| Network traffic | No explicit NetworkPolicy; SWIM gossip is cluster-scoped; gateway-to-gateway mTLS enforces peer identity | ring/rustls TLS validation + SWIM encryption | No per-tenant network isolation within cluster. SWIM gossip is unpartitioned; all operators receive all state. mTLS validates certificate identity, not tenant affiliation. |
| Compute & resources | Single operator Deployment; no per-tenant resource quotas or limits | Kubernetes Deployment spec (no limits set) | No per-tenant resource isolation. Heavy operator load impacts all tenants. |
| Configuration & secrets | Per-namespace secret references (GridNetwork.spec.tls.caSecretRef.namespace); operator reads only referenced secrets | Kubernetes RBAC (operator SA grants secret read permission) | Secrets can be shared across GridNetworks if references point to same namespace/secret. No built-in per-tenant isolation. |
| API scoping | GridNetwork CRDs are cluster-scoped (not namespaced); all operators watch all networks | operator kube Controller (watches all GridNetworks) | Cluster-scoped CRDs mean no namespace-based isolation. A compromised operator can access any GridNetwork. InferenceProvider is also cluster-scoped. |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| SWIM Membership | Cluster-wide (no per-network partition) | All Grid operators in cluster participate in single SWIM instance; no per-tenant overlay |
| CRDT State Broadcast | Per-GridNetwork (keyed by network name in SWIM payload) | Application-level filtering (operator processes only state for its GridNetwork) |
| Metrics Scraping | Per-provider (backend-specific, not shared) | Provider URL configured per InferenceProvider; no shared metrics broker |

**Multi-Tenancy Summary**:
Grid uses **logical multi-tenancy** via GridNetwork CRDs but **not strict isolation**. Multiple GridNetworks can coexist in one cluster and will not interfere (routing overlays are separate ConfigMaps, CRDT state is keyed by network name). However, there is no namespace-based or RBAC-based tenant enforcement — a compromised operator process can access any GridNetwork. Per-tenant budget tracking is supported (budgetPolicy.tenants[]), but not enforced (Grid only observes and reports, does not block). For true multi-tenant isolation, the deployment model would need to be refactored to run separate operator instances per tenant with disjoint Kubernetes namespaces and RBAC policies.
