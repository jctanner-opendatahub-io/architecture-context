## Purpose

**Short**: KServe supplies Kubernetes APIs and controllers for predictive and generative model serving; this checkout also builds the AutoGluon Python serving runtime.

**Detailed**: The Go control plane reconciles InferenceService, InferenceGraph, TrainedModel, LLMInferenceService, and local-model cache resources. It creates and manages Deployments, Services, HPAs, Jobs, PVCs/PVs, Gateway API HTTPRoutes, Kubernetes Ingresses, and supporting webhook/configuration objects. Namespace-scoped serving resources coexist with cluster-scoped ServingRuntime and ClusterServingRuntime definitions.

The Python tree contains the KServe SDK, storage initializer, protocol implementations, and framework servers. The requested product-facing image is built by `Dockerfile.konflux.autogluon`; it installs the AutoGluon Tabular and TimeSeries servers and runs `python -m autogluonserver` as an unprivileged user. The corresponding runtime definition is `kserve-autogluonserver`, which auto-selects AutoGluon model format version 1.

## Architectural Analysis

This is a broad, multi-controller KServe distribution rather than only a standalone AutoGluon process. A controller-manager deployment hosts reconciliation for legacy predictive serving, newer LLM serving, local model caching, trained models, and inference graphs. Admission webhooks validate and default serving objects and mutate newly created pods. The control plane delegates data-plane execution to framework-specific containers selected through ServingRuntime resources; AutoGluon is one of fourteen cluster runtime definitions.

The RHOAI 3.x integration surface is Gateway API aware: LLM serving reconciles Gateway and HTTPRoute resources, while the legacy predictive path retains Kubernetes Ingress reconciliation. Metrics are exposed through a kube-rbac-proxy sidecar. Workload TLS for LLM inference can be generated and stored in namespace-scoped Secrets. Analyzer coverage is partial for dynamic routes, authentication, gRPC registration, kustomize resolution, and webhook handler semantics, so those areas retain explicit unknowns below.
