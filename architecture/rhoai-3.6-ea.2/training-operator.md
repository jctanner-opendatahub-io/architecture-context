## Purpose

**Short**: Kubernetes-native operator for fine-tuning and distributed training of ML models across multiple frameworks.

**Detailed**: The Kubeflow Training Operator is a Kubernetes operator that enables distributed training and fine-tuning of machine learning models using various frameworks (PyTorch, TensorFlow, JAX, XGBoost, PaddlePaddle, MPI) through custom resource definitions. It manages the orchestration of training jobs by defining how workloads are distributed, monitoring their progress, and handling fault tolerance. The operator abstracts the complexity of distributed training configuration, allowing data scientists to submit jobs via Kubernetes native APIs or the Python SDK without deep knowledge of distributed computing patterns.

## Architectural Analysis

The Training Operator is a classic Kubernetes controller pattern, implemented as a single Go binary that manages six training framework Custom Resource Definitions (CRDs). The architecture demonstrates progressive enhancement of operator capabilities:

**Operator Structure**: Deployed as a single control plane Deployment (`training-operator`) with webhook capabilities. The operator watches all six job types across all namespaces and orchestrates corresponding Kubernetes Pods (workers, parameter servers) based on job specifications. Webhook validation prevents invalid job configurations before they enter the apiserver.

**Multi-Framework Unification**: Rather than maintaining six separate operators, the design unifies framework-specific orchestration logic under one operator. This reduces operational burden while exposing identical APIs (`.spec.template`, `.status.conditions`, `RetryPolicy`, `BackoffLimit`) across frameworks. Frameworks differ only in their `.spec` structure (e.g., PyTorchJob has `elasticPolicy`, TFJob has parameter servers).

**Workload Submission Pattern**: Users create Job objects (e.g., `PyTorchJob`) that specify framework-specific training parameters. The operator controller detects these CRs, validates them via webhook, and constructs Pods with appropriate container images, environment variables, and scheduling constraints. The operator handles horizontal scaling (e.g., elastic training for PyTorch) and job lifecycle (Creation → Running → Completion/Failure).

**Webhook Architecture**: Validating webhooks prevent invalid configurations and ensure framework-specific constraints are met before state mutation. The operator manages its own webhook certificates via secret generation. Webhook infrastructure is standard Kubernetes—ValidatingWebhookConfiguration pointing to the operator's HTTPS endpoint on port 9443 (mounted certificates from `training-operator-webhook-cert` secret).

**Security Posture**: The operator uses strict FIPS runtime configuration at build time (CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime) and enforces OpenShift TLS profile-aware configuration at runtime. Webhook communication is encrypted with dynamically discovered TLS policies. The operator does not require any privilege escalation and runs as a non-root user (UID 65532).

## Multi-Tenancy

### Tenant Model

| Aspect | Value | Source |
|--------|-------|--------|
| **Tenant boundary** | Per-namespace; each tenant's jobs isolated by Kubernetes namespace | CRD scope is Namespaced (manifests/base/crds/); operator watches resources in all namespaces |
| **Deployment model** | Single-tenant per namespace; operator is cluster-wide singleton managing all job types | manifests/base/deployment.yaml (single Deployment named training-operator, watches all namespaces) |
| **Tenant identifier** | Namespace name (implicit); no explicit tenant identity in Job spec | CRD definitions (kubeflow.org v1 Kind Job) use namespace isolation, not tenant field |

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Kubernetes namespace RBAC (RoleBindings per namespace, service account token scoped) | Kubernetes RBAC policy | Operator has cluster-admin-equivalent permissions (ClusterRole with create/delete on all job types); no per-job resource quotas enforced by operator |
| Data storage | Per-namespace PVCs (training data, model checkpoints); operator does not manage storage | Kubernetes namespace StorageClass binding; application-level job configuration | Shared storage backends (S3, NFS) can be accessed by any job; no row-level isolation at operator level |
| Network traffic | NetworkPolicy optional; no operator-enforced network isolation | Kubernetes CNI / Istio (optional) | Default: no NetworkPolicy; jobs can communicate across namespaces if network policy not deployed |
| Compute & resources | ResourceQuota per namespace; operator sets Pod limits/requests | Kubernetes ResourceQuota / LimitRange | LimitRange allows large memory requests; no hard per-job limits (application-level config only) |
| Configuration & secrets | Per-namespace Secrets for model registry, cloud credentials; operator mounts from same namespace | Kubernetes Secret RBAC | Job spec can reference Secrets only in same namespace (enforced by apiserver) |
| API scoping | All job watches are cluster-scoped (operator scans all namespaces); job status updates in same namespace | Operator fieldSelector on Job namespace | Operator uses informer watches on all namespaces; watch cache is cluster-wide |

### Shared Services

| Shared Service | Tenant Boundary | Isolation Mechanism |
|----------------|----------------|---------------------|
| Kubernetes APIServer | Cluster-wide singleton | Service account RBAC tokens (operator uses single SA, all tenants trust same operator instance) |
| Prometheus metrics endpoint | Cluster-wide | No authentication; metrics endpoint is unauthenticated (standard Prometheus scrape pattern) |

_Tenant isolation is enforced at the Kubernetes namespace level. The Training Operator itself is a single cluster-wide instance that schedules jobs in each namespace. Isolation relies entirely on Kubernetes RBAC policies and network policies. The operator does not implement per-tenant data separation or rate limiting._
