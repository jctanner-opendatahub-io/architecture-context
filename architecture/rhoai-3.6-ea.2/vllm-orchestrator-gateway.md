## Purpose

**Short**: Provides configurable OpenAI-compatible chat-completions routes that send requests through the FMS Guardrails Orchestrator and apply detector-specific fallback responses.

**Detailed**: The gateway reads a YAML configuration containing an orchestrator destination, detector definitions, and named routes. Each configured route becomes `/{route.name}/v1/chat/completions`; the gateway injects the selected detector configuration into the request and forwards it to the orchestrator's detection endpoint.

For non-streaming requests it returns the orchestrator response, replacing the choices with a configured fallback message when detections are present. For streaming requests it converts upstream SSE chunks into Axum SSE events and applies the same fallback behavior to detected output. Authorization and `x-forwarded-*` headers are forwarded to the orchestrator.

## Architectural Analysis

This is a small, single-binary Rust gateway built with Tokio and Axum. Its route surface is configuration-driven rather than statically enumerated: the supplied configuration exposes `pii` and `passthrough` routes, while other deployments can add routes without changing the binary. The service has no Kubernetes API integration, controller loop, CRDs, RBAC, persistence, or local multi-tenant control plane.

The gateway is a policy and protocol adapter in front of the Guardrails Orchestrator. It keeps detector selection and fallback policy in route configuration, while delegating detection and generation orchestration downstream. The inbound listener is plain HTTP in the application; outbound TLS/mTLS is enabled when the configured certificate and key files exist. Because the certificate presence check controls the scheme, a deployment missing those files falls back to HTTP and logs a warning; this should be treated as an operational security dependency.

The analyzer confirms the Rust component and dependency inventory but did not extract complete runtime endpoint, service, ingress, or deployment facts for Rust. The endpoint and integration details below are therefore based on direct source and configuration inspection, with deployment exposure left unknown where no manifests are present.
