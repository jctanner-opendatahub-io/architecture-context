## Purpose

**Short**: Kubernetes module operator that manages the lifecycle of the MCP (Model Context Protocol) lifecycle operand, reconciling MCPLifecycleOperator custom resources to deploy, configure, and garbage-collect MCP server infrastructure within the RHOAI platform. [source: cmd/main.go:63, 108, internal/controller/mcplifecycleoperator_reconciler.go:108, config/crd/bases/components.platform.opendatahub.io_mcplifecycleoperators.yaml:2]

**Detailed**: mcp-lifecycle-module-operator is a two-tier Kubernetes operator built with controller-runtime. The module operator (this component) watches for MCPLifecycleOperator cluster-scoped custom resources and reconciles them by rendering embedded Kustomize manifests into a set of operand resources — including a secondary Deployment (mcp-lifecycle-operator-controller-manager), RBAC policies, ServiceMonitors, NetworkPolicies, and MCPServer CRDs — which it applies via Server-Side Apply (SSA). The operator detects the platform distribution (RHOAI vs standalone) by reading a ConfigMap and adapts its status reporting accordingly. It fetches the cluster's TLS profile from the OpenShift APIServer resource to configure TLS cipher suites for the operand, falling back to the Intermediate profile on non-OpenShift clusters. Condition management and phase tracking use shared types from odh-platform-utilities, enabling the platform's component health aggregation. The operator manages resource cleanup through label-based garbage collection when resources are removed or the CR management state is set to `Removed`. [source: cmd/main.go:63-168, internal/controller/mcplifecycleoperator_reconciler.go:108-217, 400-458, 470-502, internal/controller/tls.go:21-44, api/v1alpha1/mcplifecycleoperator_lifecycle.go:20-122]

## Architectural Analysis

The mcp-lifecycle-module-operator follows the established RHOAI module operator pattern where a lightweight "module" operator manages a heavier "lifecycle" operand. The module operator itself is a single-binary Go controller-runtime application (`/manager`) that reconciles one cluster-scoped singleton CR (MCPLifecycleOperator). On each reconciliation cycle, it renders embedded Kustomize manifests with runtime parameters — including the operand image reference (`RELATED_IMAGE_ODH_MCP_LIFECYCLE_OPERATOR_IMAGE`), the target namespace (`SYSTEM_NAMESPACE`), and the cluster's TLS profile — then applies the resulting resource set via Server-Side Apply with a dedicated field owner. [source: cmd/main.go:90-148, internal/controller/mcplifecycleoperator_reconciler.go:147-217]

The two-tier design separates concerns: the module operator handles operand deployment, upgrade, and garbage collection, while the deployed operand (mcp-lifecycle-operator-controller-manager) manages MCPServer namespaced resources that represent actual MCP protocol server instances. The module operator watches its own managed resources (Deployments, Services, ServiceAccounts, RBAC objects, CRDs) using a label-based predicate (`platform.opendatahub.io/part-of`) to filter cache entries and trigger re-reconciliation when managed resources drift. It also watches a platform ConfigMap to detect distribution name and version changes for status reporting. [source: internal/controller/mcplifecycleoperator_reconciler.go:470-502, 422-458]

TLS configuration is platform-aware: on OpenShift clusters, the operator reads the cluster-wide APIServer resource to extract the active TLS profile (cipher suites and minimum version), passing these parameters into the operand manifests. On non-OpenShift clusters, it falls back to the Intermediate TLS profile (TLS 1.2+). This design ensures the operand inherits the cluster administrator's TLS policy without hardcoding cipher choices. [source: internal/controller/tls.go:21-44, internal/controller/mcplifecycleoperator_reconciler.go:159-166]

The operator uses odh-platform-utilities extensively for shared platform behaviors: condition management with standard condition types (Ready, ProvisioningSucceeded, Degraded), phase computation, component release status reporting, and the deploy/garbage-collection subsystem. This dependency creates a tight coupling with the platform's component lifecycle contract but ensures consistent status semantics across all RHOAI module operators. [source: api/v1alpha1/mcplifecycleoperator_lifecycle.go:20-122, cmd/main.go:118-125]

The RBAC model defines two distinct permission scopes: the module operator's own ClusterRole (mcp-lifecycle-module-operator-manager-role, 20 rules) for managing CRDs, Deployments, RBAC objects, and other infrastructure; and the operand's ClusterRole (mcp-lifecycle-operator-manager-role, 9 rules) with narrower permissions for MCPServer lifecycle management. RBAC aggregation labels on the operand's ClusterRoles (admin/editor/viewer) integrate MCPServer permissions into Kubernetes built-in roles, enabling self-service MCPServer management by namespace users. [source: config/rbac/role.yaml:2, internal/controller/resources/mcp-lifecycle-operator.yaml:1793, 1877-1934]

## Data Flows

- **CR reconciliation flow:** The operator watches for MCPLifecycleOperator CR events and triggers a reconciliation cycle. It reads the platform ConfigMap to determine distribution context, fetches the cluster TLS profile from the OpenShift APIServer resource, renders embedded Kustomize manifests with these parameters, and applies the resulting resources via SSA to the target namespace. After applying, it verifies operand Deployment readiness and updates CR status conditions. [source: cmd/main.go:90-168, internal/controller/mcplifecycleoperator_reconciler.go:108-217, 422-458, internal/controller/tls.go:21-38]
- **Managed resource watches:** The controller watches 9 Kubernetes resource types (ConfigMap, Deployment, ServiceAccount, Service, ClusterRole, ClusterRoleBinding, Role, RoleBinding, CRD) and conditionally the OpenShift APIServer resource. All managed-resource watches use a label predicate filtering on `platform.opendatahub.io/part-of=mcp-lifecycle-operator`; the ConfigMap watch uses a name/namespace predicate. Each watch event re-enqueues the singleton MCPLifecycleOperator CR. [source: internal/controller/mcplifecycleoperator_reconciler.go:470-502]
- **Operand deployment:** The module operator deploys the mcp-lifecycle-operator-controller-manager as a secondary Deployment, along with its RBAC policies, ServiceMonitor, NetworkPolicies, and MCPServer CRD. The operand image is injected via the `RELATED_IMAGE_ODH_MCP_LIFECYCLE_OPERATOR_IMAGE` environment variable or defaults to the manifest-embedded image. [source: cmd/main.go:133-148, internal/controller/mcplifecycleoperator_reconciler.go:170-194]
- **Security context:** The module operator authenticates to the Kubernetes API via in-cluster ServiceAccount token. Health probes on :8081 are unauthenticated by design. The operand's metrics service on port 8443 uses RBAC-gated access (TokenReview/SubjectAccessReview). MCPServer resources are accessible to namespace users via RBAC aggregation into built-in admin/editor/viewer roles. [source: cmd/main.go:90, 155, 159, internal/controller/resources/mcp-lifecycle-operator.yaml:1877, 1958, 2032]
