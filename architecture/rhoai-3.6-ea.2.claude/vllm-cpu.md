## Purpose

**Short**: vllm-cpu is a high-throughput LLM inference and serving engine that exposes OpenAI-compatible, Anthropic-compatible, and custom HTTP APIs, with an optional gRPC serving mode backed by the smg-grpc-servicer package. [source: Dockerfile.konflux.cpu:170, pyproject.toml:22, vllm/entrypoints/grpc_server.py:8-9]

**Detailed**: vllm-cpu provides CPU-optimized large language model inference as a standalone application service within the RHOAI model serving infrastructure. The primary entrypoint launches a FastAPI-based OpenAI API-compatible server (`vllm.entrypoints.openai.api_server`) that exposes 47 HTTP endpoints spanning chat completions, embeddings, reranking, scoring, tokenization, audio transcription, and administrative operations. An optional gRPC serving mode (`vllm.entrypoints.grpc_server`) provides the VllmEngine service on port 50051 with standard gRPC health checking for Kubernetes probes. Authentication is conditional: Bearer token validation via ASGI middleware is applied only when an API key is configured, and guards only paths prefixed with `/v1`, `/v2`, or `/inference`. The repository produces container images for multiple architectures and accelerators (CPU, HPU, ROCm, TPU, ppc64le, s390x) using UBI9-based Dockerfiles, with the Konflux CPU variant (`Dockerfile.konflux.cpu`) serving as the production build for RHOAI. [source: Dockerfile.konflux.cpu:170, vllm/entrypoints/openai/api_server.py:257-261, vllm/entrypoints/grpc_server.py:56-118, vllm/entrypoints/serve/utils/server_utils.py:41-92]

## Architectural Analysis

vllm-cpu follows a modular router architecture where API surface areas are organized as independent FastAPI `APIRouter` modules under `vllm/entrypoints/`. Each domain (OpenAI chat completions, Anthropic messages, pooling/embedding, speech-to-text, SageMaker compatibility, disaggregated inference) registers its routes into the central application. This design allows the server to selectively load endpoint groups based on the model's supported tasks at startup.

Authentication is implemented as an ASGI middleware layer (`AuthenticationMiddleware`) that intercepts requests before they reach route handlers. The middleware uses a guarded-prefix strategy: only paths starting with `/v1`, `/v2`, or `/inference` require Bearer token authentication, leaving operational endpoints (`/health`, `/ready`, `/readyz`, `/load`, `/docs`) accessible without credentials. Token comparison uses SHA-256 hashing with constant-time comparison via `secrets.compare_digest`, mitigating timing attacks. This authentication is entirely opt-in — it activates only when `--api-key` or the `VLLM_API_KEY` environment variable is set. [source: vllm/entrypoints/serve/utils/server_utils.py:41-92, vllm/entrypoints/openai/api_server.py:257-261]

The gRPC serving mode provides an alternative interface via `vllm.entrypoints.grpc_server`, using the external `smg-grpc-servicer` package to implement the `VllmEngine` service. This mode runs as a separate process (not alongside the HTTP server) and includes standard `grpc.health.v1.Health` service for Kubernetes liveness/readiness probes and server reflection for tooling compatibility. The gRPC server binds to an insecure port (default 50051) with no built-in TLS; transport encryption would need to be provided by a service mesh or sidecar proxy. [source: vllm/entrypoints/grpc_server.py:88-118]

The Konflux production build (`Dockerfile.konflux.cpu`) uses `registry.redhat.io/ubi9/ubi-minimal-pqc` as the base image and sets `GRPC_PYTHON_BUILD_SYSTEM_OPENSSL=1` to build the gRPC Python extension against system OpenSSL rather than bundled BoringSSL, ensuring that TLS operations use the platform's validated cryptographic provider. Python's standard `ssl` and `hashlib` modules inherit OpenSSL from the UBI base, but no explicit FIPS mode enforcement is configured at the application level. [source: Dockerfile.konflux.cpu:8, 20]

## Data Flows

- **Inference request flow:** Clients send inference requests to the HTTP API (FastAPI) or gRPC API (smg-grpc-servicer). HTTP requests to guarded paths (`/v1`, `/v2`, `/inference`) pass through the optional `AuthenticationMiddleware` for Bearer token validation before reaching route handlers. Route handlers delegate to the `AsyncLLM` engine for model inference. [source: vllm/entrypoints/openai/api_server.py:257-261, vllm/entrypoints/serve/utils/server_utils.py:77-92, vllm/entrypoints/grpc_server.py:77-85]
