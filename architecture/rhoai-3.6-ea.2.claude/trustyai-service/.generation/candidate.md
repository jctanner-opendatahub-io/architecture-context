## Purpose

**Short**: TrustyAI Service is a Python FastAPI application providing AI model explainability, fairness, and drift detection metrics, served via Hypercorn behind kube-rbac-proxy with optional TLS and platform-delegated authentication. [source: src/trustyai_service/main.py:136-140, src/trustyai_service/main.py:370-392, pyproject.toml:2-4]

**Detailed**: TrustyAI Service is a Python-based AI observability service that computes and exposes fairness metrics (Statistical Parity Difference, Disparate Impact Ratio), drift detection metrics (Kolmogorov-Smirnov, Jensen-Shannon, MMD, CompareMeans), and model explainability (LIME, SHAP, PDP, counterfactual). It runs on Hypercorn with a dual-port architecture: the main API binds to loopback on port 8081 behind kube-rbac-proxy for authenticated access, while health probes and KServe/ModelMesh inference consumers bind to port 8080 for internal cluster traffic. An optional HTTPS listener on port 4443 uses a PolicyAwareConfig that delegates cipher and TLS version selection to the operating system crypto policy, supporting FIPS mode without application-level overrides. Data is stored via PVC (HDF5) by default or optionally in MariaDB with TLS support. A background scheduler periodically computes Prometheus metrics for configured metric requests. [source: src/trustyai_service/main.py:136-140, 365-416, src/trustyai_service/service/tls.py:1-41, src/trustyai_service/service/data/storage/__init__.py:96-139, src/trustyai_service/endpoints/routes.py:29-85]

## Architectural Analysis

TrustyAI Service employs a split-listener architecture that separates authenticated API traffic from internal cluster communication. The main FastAPI application serves fairness, drift, explainability, and metadata endpoints on port 8081, bound to loopback (`127.0.0.1`) so that only kube-rbac-proxy on the same pod can reach it. Health probes and inference data consumers run on a separate `health_app` FastAPI instance on port 8080, bound to all interfaces for kubelet and KServe/ModelMesh access. An optional HTTPS listener on port 4443 provides direct TLS access using system-policy-aware cipher selection. [source: src/trustyai_service/main.py:370-416]

The service supports two storage backends selected at runtime via `SERVICE_STORAGE_FORMAT`: PVC-based HDF5 file storage (default) and MariaDB with optional TLS via CA certificate. A singleton `GlobalStorageInterface` pattern ensures a single storage connection is shared across endpoints. The MariaDB backend supports both direct environment variable configuration and Quarkus-style variables for compatibility with the former Java TrustyAI service. [source: src/trustyai_service/service/data/storage/__init__.py:15-139]

Endpoint registration uses a feature-flag gating system where metric groups (fairness, drift, explainer) can be individually enabled or disabled. Fairness metrics additionally register legacy `/dir` and `/spd` prefixes alongside the modern `/metrics/group/fairness/` paths. A background asyncio task runs a Prometheus scheduler at a configurable interval (default 30s) to publish pre-computed metric values for scraping. [source: src/trustyai_service/main.py:101-113, 167-230, src/trustyai_service/endpoints/routes.py:29-49]

The `PolicyAwareConfig` subclass of Hypercorn's Config is a deliberate design decision: Hypercorn hardcodes its cipher list and minimum TLS version, which would override the system crypto policy set by `update-crypto-policies`. By delegating to `ssl.create_default_context`, the service automatically honors the cluster TLS profile and FIPS crypto policy without application-level overrides. [source: src/trustyai_service/service/tls.py:1-41]

## Data Flows

- **Authenticated API flow:** External clients connect through kube-rbac-proxy, which authenticates the request and forwards it to the main FastAPI application on loopback port 8081. The application processes fairness, drift, explainability, and metadata requests without additional application-level authentication. [source: src/trustyai_service/main.py:370-392]
- **Inference data ingestion:** KServe inference loggers send CloudEvents to `POST /` on port 8080; ModelMesh agents send KServe v2 payloads to `POST /consumer/kserve/v2` on the same port. Both are received by the `health_app` FastAPI instance. Input and output payloads are reconciled by ID and persisted to the configured storage backend. [source: src/trustyai_service/main.py:336-340, src/trustyai_service/endpoints/consumer/consumer_endpoint.py:74-138]
- **Metrics publishing:** A background asyncio task runs at a configurable interval (default 30s), computing scheduled metric requests and publishing results to Prometheus client counters/gauges exposed at `/q/metrics` on port 8080. [source: src/trustyai_service/main.py:101-113, src/trustyai_service/endpoints/routes.py:85]
- **Storage:** Data persists to PVC as HDF5 files (default) or to MariaDB over TCP port 3306 with optional TLS via CA certificate. Database credentials are read from environment variables (`DATABASE_PASSWORD` or `QUARKUS_DATASOURCE_PASSWORD`). [source: src/trustyai_service/service/data/storage/__init__.py:48-139]
