## Purpose

**Short**: Kubernetes operator that reconciles the cluster-scoped AIGateway custom resource to manage AI gateway infrastructure, including batch gateway (llm-d) and Models-as-a-Service sub-modules, Gateway API routing, and Kuadrant API policy enforcement on the RHOAI platform. [source: config/crd/bases/components.platform.opendatahub.io_aigateways.yaml:2, internal/controller/aigateway/aigateway.go:149, cmd/operator/operator.go:124]

**Detailed**: The ai-gateway-operator is a standalone module operator for Red Hat OpenShift AI that manages the AI Gateway platform component. It reconciles the cluster-scoped `AIGateway` CRD (`components.platform.opendatahub.io/v1alpha1`) and conditionally deploys two sub-modules based on their `managementState` spec fields: a batch gateway for llm-d batch inference workloads (`spec.batchGateway`) and a MaaS (Models-as-a-Service) controller for external model, tenant, and subscription management (`spec.modelsAsAService`). The operator uses the opendatahub-operator reconciler SDK (`github.com/opendatahub-io/opendatahub-operator/v2`) for kustomize-based manifest rendering and ordered deployment, and integrates with Gateway API for HTTPRoute management, Kuadrant for authentication and rate-limiting policy enforcement, cert-manager for TLS certificate lifecycle, Istio networking for traffic management, and prometheus-operator for observability. [source: api/components/v1alpha1/aigateway_types.go:20, cmd/operator/operator.go:124, internal/controller/aigateway/aigateway.go:149, config/rbac/role.yaml:2]

## Architectural Analysis

The ai-gateway-operator follows the opendatahub-operator module-operator pattern: a standalone controller-runtime process that reconciles a single cluster-scoped component CRD (`AIGateway`) using kustomize-based manifest rendering with ordered deployment actions. The reconciler chain (`NewReconciler` in `aigateway_controller.go`) registers ownership watches on 10 Kubernetes resource types—including Deployments, RBAC resources, Services, CRDs, and ValidatingWebhookConfigurations—and an additional event-mapped watch on platform-managed ConfigMaps whose changes trigger re-reconciliation to keep status.releases current. [source: internal/controller/aigateway/aigateway_controller.go:145-198]

The operator's most distinctive architectural characteristic is its sub-module composition model. Rather than deploying a fixed set of manifests, it conditionally includes two independent manifest sets—batch-gateway (llm-d) and MaaS controller—based on their respective `managementState` fields in the AIGateway spec. The MaaS sub-module has a graceful teardown protocol: when set to `Removed`, the operator checks whether active MaaS resources still exist before tearing down, preventing premature deletion of in-use infrastructure. [source: internal/controller/aigateway/aigateway.go:142-205]

The RBAC surface is extensive (61 rules on the manager-role ClusterRole), reflecting the operator's role as an orchestrator across multiple Kubernetes ecosystem integrations. The operator manages Gateway API resources (HTTPRoutes, Gateways, ReferenceGrants) for traffic routing, Kuadrant CRDs (AuthPolicies, RateLimitPolicies, TokenRateLimitPolicies, TelemetryPolicies) for API policy enforcement, cert-manager Certificates for TLS lifecycle, Istio networking resources (DestinationRules, EnvoyFilters, ServiceEntries) for service mesh integration, and the full MaaS API surface (maas.opendatahub.io group: tenants, subscriptions, auth policies, model references). It also watches Authorino CRs to verify authentication infrastructure availability and reads KServe InferenceService/LLMInferenceService for model serving state. [source: config/rbac/role.yaml:2, cmd/operator/operator.go:124]

The operator deploys as a single-pod Deployment with leader election enabled by default. It disables cache reads for ConfigMaps and Secrets (forcing read-through for freshness and security sensitivity) while enabling cache reads for unstructured objects used during kustomize rendering. The watch cache is scoped to the configured applications namespace and cluster-scoped resources, limiting memory consumption. Configuration is loaded from a mounted ConfigMap directory (via `ODH_MODULE_OPERATOR_CONFIGURATION_PATH`), environment variables with `ODH_MODULE_OPERATOR_` prefix, and built-in defaults, in ascending order of precedence. [source: cmd/operator/operator.go:84-122, pkg/config/config.go:69-95]

The Konflux build configures FIPS compliance with `GOEXPERIMENT=strictfipsruntime` and `CGO_ENABLED=1`, producing a dynamically-linked binary on a UBI 9 ubi-minimal-pqc (post-quantum cryptography) runtime base image. The upstream Containerfile uses `CGO_ENABLED=0` (static linking) without FIPS flags, reflecting the divergence between community and product builds. [source: Containerfile.konflux:4,33,38, Containerfile:39]
