Authentication Summary:
- Kubernetes API: kubeconfig credential chain
  - Bearer token, client certificate, or OIDC
  - SelfSubjectAccessReview pre-flight for privileged operations
  - Propagated via k8s.io/cli-runtime ConfigFlags

- TrustYAI Service: Bearer token from kubeconfig REST config
  - TLS 1.2+ with InsecureSkipVerify=true (self-signed in-cluster routes)
  - Discovered via OpenShift Route lookup (label or name match)

- MCP Server: No additional auth (localhost-only binding)
  - Inherits kubeconfig credentials from parent CLI process
  - Tool calls execute with same RBAC permissions as CLI user

FIPS Compliance:
- Build: GOEXPERIMENT=strictfipsruntime, CGO_ENABLED=1, -tags strictfipsruntime
- Runtime: OpenSSL-backed crypto via UBI go-toolset + ose-cli-rhel9
- Risk: InsecureSkipVerify=true on TrustYAI connections bypasses certificate validation
  (documented as intentional for self-signed in-cluster routes)

Secrets:
- No operator-managed secrets (CLI tool)
- Credentials sourced from user kubeconfig file
- Bearer tokens passed in-memory to HTTP clients
