## Diagram Descriptions

### Component Dependency Graph
Shows how RHOAI 3.6-ea.2's 76 components relate to each other. rhods-operator is the platform root, orchestrating 15+ module operators and core controllers. kserve is the most interconnected serving component with 13 CRDs and 30 webhooks. Color-coded by role: blue (core controllers), green (ODH components), light blue (module operators), orange (new inference engines), purple (observability), yellow (user workloads).

### Platform Network Topology
Complete network architecture showing the dual-gateway ingress model (data-science-gateway for traditional serving/notebooks, maas-default-gateway for MaaS API), legacy OpenShift Routes for monitoring, and the LLM-D disaggregated inference data path. Includes exact port numbers, protocols, encryption, and authentication mechanisms at each layer.

**Two formats provided**:
- **Mermaid (.mmd)**: Visual diagram with color-coded trust zones (external, ingress, service mesh, egress). Great for presentations and architecture discussions.
- **ASCII (.txt)**: Precise text format with full details on every gateway, auth chain, namespace, and ServiceAccount. Required for SAR submissions and compliance documentation.

Both formats contain the same information, just different representations.

### Cross-Component Workflows
Sequence diagrams showing 5 end-to-end workflows:
1. **KServe InferenceService deployment**: Dashboard → kserve → odh-model-controller → data-science-gateway → kube-auth-proxy → model server
2. **MaaS external model inference**: Client → maas-default-gateway → praxis-extproc (dual-stage) → Kuadrant/Authorino → maas-api → external provider
3. **Notebook creation and access**: Dashboard → kubeflow → kube-rbac-proxy sidecar injection → data-science-gateway → kube-auth-proxy → notebook
4. **Data Science Pipeline execution**: Dashboard → DSPO → DSP API → Argo Workflows → ml-metadata
5. **LLM-D disaggregated inference**: Envoy → EPP (ExtProc) → InferencePool → vLLM prefill → RDMA KV-cache → vLLM decode

### Platform Security Overview
Visual representation of the security architecture including:
- **7 authentication mechanisms** (ext_authz, Kuadrant AuthPolicy, kube-rbac-proxy, bearer token, TLS profile, ServiceAccount RBAC, leader election)
- **8 key ServiceAccounts** and their ClusterRole bindings
- **213 webhooks** across 18 components (all failurePolicy: Fail)
- **Gateway authentication chains** (data-science-gateway and maas-default-gateway)
- **Container security**: FIPS Go (strictfipsruntime), UBI9 PQC base images, non-root execution, and FIPS gap in Rust components
- **TLS configuration**: Gateway TLS, webhook TLS, metrics TLS, optional Istio mTLS
- **Service mesh security**: EnvoyFilter ext_authz, ext_proc, sidecar injection, DestinationRules

### Platform Observability
Maps all monitoring and observability infrastructure:
- **Prometheus scrape targets**: 46+ operator metrics endpoints via kube-rbac-proxy on port 8443
- **Metrics access routes**: 3 OpenShift Routes (cluster proxy, namespace proxy, Thanos querier) with TLS passthrough and kube-rbac-proxy SAR enforcement
- **Distributed tracing**: Optional OpenTelemetry OTLP from maas-api, odh-model-controller, odh-dashboard, trustyai-service-operator
- **Webhook availability**: 213 webhooks (all Fail policy) — outage blocks resource creation
- **Leader election health**: 19 components using Lease-based leader election
- **Pipeline observability**: DSP API, ml-metadata lineage, Argo Workflows status

### Platform Maturity Dashboard
High-level metrics covering:
- **76 components** with ~420 container entrypoints, 78 Go executables, 54 Python packages, 15 Rust services
- **146 CRDs** across 31 components, **213 webhooks** across 18 components
- **3 production Gateways** with HTTPRoute and GRPCRoute, plus legacy Routes
- **6 model serving paths** (KServe, LLMInferenceService, LLM-D, MaaS, Guardrails, Batch)
- **Security**: FIPS Go (strictfipsruntime), UBI9 PQC, mixed mTLS, FIPS gap in Rust
- **API maturity**: v1alpha1 (majority), v1beta1 (kserve, kubeflow, kueue), v1 (feast, training-operator)
- **Deployment**: Leader election HA, unresolved disconnected support, partial multi-arch
- **New in 3.6-ea.2**: 8+ new components including LLM-D, OpenShell, Workspaces, Trainer v2
