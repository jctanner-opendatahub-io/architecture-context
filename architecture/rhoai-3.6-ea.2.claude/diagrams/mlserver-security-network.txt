RBAC Summary:
- No ClusterRoles or RoleBindings defined by MLServer
- MLServer is a runtime container, not a Kubernetes operator
- It does not interact with the Kubernetes API directly
- All RBAC enforcement is handled by the kube-rbac-proxy sidecar

Authentication & Authorization:
- All REST and gRPC endpoints: kube-rbac-proxy sidecar (platform-delegated)
- Enforcement: OpenShift OAuth / ServiceAccount token validation
- Metrics endpoint (8082): No authentication (standard Prometheus scrape)

Runtime Security:
- Trusted runtimes allowlist restricts which model frameworks can be loaded
- CPU image allows: LightGBM, ONNX, Scikit-Learn, XGBoost
- CUDA image allows: ONNX only
- Prevents arbitrary code execution through untrusted runtime paths

FIPS Compliance:
- No application-level TLS (gRPC uses add_insecure_port, REST uses plain HTTP)
- No direct cryptographic operations in application code
- FIPS compliance inherited from AIPCC base image OpenSSL configuration
- Transport security delegated to platform (kube-rbac-proxy, Istio/Service Mesh)

Secrets:
- No secrets managed by MLServer directly
- Model storage credentials handled by KServe storage initializer
