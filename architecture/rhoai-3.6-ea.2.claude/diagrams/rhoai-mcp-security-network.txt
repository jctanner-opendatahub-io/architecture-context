Authentication Architecture:
- Transport-level: OIDCAuthMiddleware
  - JWT validation via JWKS endpoint
  - Kubernetes TokenReview fallback
  - Excluded paths: /health, /.well-known/oauth-protected-resource
- Tool-level: RBAC filtering via SubjectAccessReview
  - Per-tool access control based on K8s permissions
  - Tools filtered from listing if user lacks permissions
- Workflow-level: HMAC-SHA256 signed tokens
  - Prevents skipping prerequisite steps
  - Python hmac module (uses OpenSSL when available)

FIPS Compliance Notes:
- Python application on AIPCC base image (OpenSSL available)
- cryptography ==50.0.0 (OpenSSL backend, FIPS-capable)
- PyJWT[crypto] for JWT RS256/ES256 operations
- HMAC-SHA256 via Python stdlib hmac (uses OpenSSL when available)
- No explicit FIPS mode opt-in; relies on AIPCC base image OpenSSL config

Kubernetes Auth Strategies:
- Strategy 1: Service Account Token (default, pod-mounted)
- Strategy 2: User-Token Forwarding (passes caller's bearer token to K8s API)
- Strategy 3: Impersonation (SA credentials + Impersonate-User/Group headers)
