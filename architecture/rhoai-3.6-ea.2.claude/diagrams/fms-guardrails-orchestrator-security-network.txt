- TLS client CA cert (Opaque) - HTTP server mTLS client verification, provisioned by platform operator, rotation unknown
- API tokens (Opaque, env var) - Downstream service authentication, provisioned by platform operator, rotation unknown
- Downstream TLS certs (Opaque) - Per-service TLS client configuration, provisioned by platform operator, rotation unknown

RBAC Summary:
- No ClusterRoles or RoleBindings defined (application-level service, not a Kubernetes operator)

Authentication & Authorization:
- /api/v1/*, /api/v2/* (POST): Header passthrough to downstream services
- /api/v1/*, /api/v2/* (POST): X-Forwarded-Access-Token rewrite to Authorization: Bearer
- /health, /info (GET): Unauthenticated
- All endpoints (ALL): Optional TLS / mTLS at transport layer via Rust TLS acceptor

FIPS Compliance Warning:
- Crypto provider: ring (explicitly selected via Cargo.toml feature flags)
- ring is NOT a FIPS-validated provider
- FIPS compliance requires switching to aws-lc-rs with FIPS features
  or delegating TLS termination to a FIPS-capable proxy (e.g., Envoy/Istio)
- OpenSSL is referenced in Dockerfiles but not used as application TLS provider
