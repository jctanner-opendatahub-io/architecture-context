AUTHENTICATION & AUTHORIZATION SUMMARY:
- Health probes (:8081/healthz, :8081/readyz): Unauthenticated by design
- Admission webhooks: Kubernetes admission authentication (API server client cert)
- Backend REST API: Request-header authentication (upstream proxy sets identity
  headers) + Kubernetes SubjectAccessReview authorization per resource per call
- Controller: ServiceAccount token for Kubernetes API access

FIPS COMPLIANCE:
- Controller: FIPS-compliant (CGO_ENABLED=1, GOEXPERIMENT=strictfipsruntime,
  UBI9 PQC base image, dynamic linking with OpenSSL)
- Backend: NOT FIPS-compliant in current checkout (CGO_ENABLED=0, static linking,
  distroless base, no Konflux Dockerfile)

SECRETS:
- No explicitly declared secrets in architecture documentation
- ServiceAccount tokens used for Kubernetes API authentication
- TLS certificates managed by controller-runtime / cert-manager for webhooks
- Backend TLS optional via runtime cert-file/key-file flags

CRDs:
- kubeflow.org/v1beta1/Workspace (Namespaced) - Interactive workspace instances
- kubeflow.org/v1beta1/WorkspaceKind (Cluster) - Workspace templates/definitions
