Secret Resolution Pattern:
- Entrypoint resolves _FILE environment variables at startup
- Reads Kubernetes-mounted secret files into env vars
- Avoids /proc exposure of sensitive values
- Variables: POSTGRES_PASSWORD_FILE, MILVUS_TOKEN_FILE, etc.

Authentication & Authorization:
- Mechanism: OAuth2 JWT (optional, when AUTH_ISSUER configured)
- Token validation: JWKS-based (fetched from AUTH_ISSUER endpoint)
- TLS for JWKS: Configurable (AUTH_VERIFY_TLS, AUTH_TLS_CAFILE)
- Access policy (3 rules):
  1. Public read: Unauthenticated access to system resources
  2. Create: Requires valid authenticated token
  3. Owner-scoped CRUD: User must own the resource

RBAC Summary:
- No Kubernetes RBAC roles defined in this component
- RBAC is managed by ogx-operator (lifecycle manager)

Service Mesh Configuration:
- Application runs with --insecure flag (no application-level TLS)
- TLS termination expected at platform ingress (OpenShift Route / Istio)
- No PeerAuthentication or AuthorizationPolicy defined in component

Secrets:
- PostgreSQL credentials: POSTGRES_USER, POSTGRES_PASSWORD (via _FILE mount)
- Milvus token: MILVUS_TOKEN (via _FILE mount)
- OAuth2 client: AUTH_ISSUER, AUTH_TLS_CAFILE
- vLLM connection: VLLM_URL, VLLM_TLS_VERIFY
- OpenTelemetry: OTEL_SERVICE_NAME (activation trigger)

FIPS Compliance:
- Python application, no compiled crypto binaries
- Inherits OpenSSL from AIPCC/UBI base image
- No explicit FIPS mode enforcement at application level
- TLS delegated to platform ingress
