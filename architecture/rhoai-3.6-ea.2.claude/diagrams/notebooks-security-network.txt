CRITICAL SECURITY NOTE:
  Notebook images explicitly disable ALL built-in authentication:
  - JupyterLab: token='' and password disabled in start-notebook.sh
  - code-server: --auth none flag in run-code-server.sh
  These images are NOT safe to expose without the OAuth proxy sidecar.
  The odh-notebook-controller MUST inject the OAuth proxy for secure operation.

Secrets:
  - PULL_SECRET (env var) - Container image pull credentials
  - GITHUB_TOKEN (env var) - CI/automation (not runtime)
  - GEMINI_API_KEY (env var) - CI/automation (not runtime)
  - RENOVATE_TOKEN (env var) - CI/automation (not runtime)
  - JIRA_API_TOKEN (env var) - CI/automation (not runtime)
  - JIRA_TOKEN (env var) - CI/automation (not runtime)
  - JIRA_OAUTH_CLIENT_SECRET (env var) - CI/automation (not runtime)
  Note: These are CI/automation credentials, NOT runtime notebook secrets.

FIPS Compliance:
  - Base: UBI9 with system OpenSSL (FIPS-capable when host in FIPS mode)
  - compat-openssl11 installed for FIPS compliance scanning
  - cryptography==49.0.0 (uses OpenSSL, FIPS-capable)
  - Risk: pycryptodome==3.23.0 available as user dependency (not FIPS-validated)
    but not used by notebook platform itself

Authentication & Authorization:
  - JupyterLab API: All methods, platform-delegated OAuth proxy
    Enforcement: odh-notebook-controller sidecar
    Policy: Token/password auth disabled; all access gated by OAuth proxy
  - Code-Server API: All methods, platform-delegated OAuth proxy
    Enforcement: odh-notebook-controller sidecar
    Policy: Built-in auth disabled; nginx routes via NB_PREFIX behind OAuth proxy

RBAC Summary:
  - No ClusterRoles or RoleBindings defined by this component
  - RBAC is managed by odh-notebook-controller, not the notebook images
