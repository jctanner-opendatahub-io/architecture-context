## Purpose

**Short**: mcp-lifecycle-operator manages the lifecycle of Model Context Protocol (MCP) servers on Kubernetes, reconciling MCPServer custom resources into Deployments, Services, and NetworkPolicies with configurable TLS and authentication. [source: cmd/main.go:60, 188-198, internal/controller/mcpserver_controller.go:653-673]

**Detailed**: mcp-lifecycle-operator is a Kubernetes operator that manages MCP (Model Context Protocol) server instances via the MCPServer custom resource (mcp.x-k8s.io/v1alpha1). When users create or update MCPServer resources, the MCPServerReconciler creates and maintains associated Deployments, Services, and NetworkPolicies. The operator watches ConfigMaps and Secrets referenced by MCPServer specs and triggers re-reconciliation when they change, using field indexers for efficient lookup. It supports configurable TLS settings via environment variables (TLS_MIN_VERSION, TLS_CIPHER_SUITES) and can propagate these to managed MCP server containers when PROPAGATE_TLS_ENV_VARS is enabled. The operator runs as a single-replica Deployment with leader election support, exposes health and readiness probes on port 8081 (HTTP, unauthenticated), and serves Prometheus metrics on port 8443 with TLS encryption and TokenReview/SubjectAccessReview authentication. It is synced from the upstream opendatahub-io/mcp-lifecycle-operator repository. [source: cmd/main.go:60, 144, 164, 188-198, 205, 209, cmd/tlsconfig.go:17-26, internal/controller/mcpserver_controller.go:653-673]

## Architectural Analysis

The mcp-lifecycle-operator follows the standard controller-runtime operator pattern with a single reconciler (MCPServerReconciler) managing the full lifecycle of MCP server workloads. The reconciler uses an ownership-based resource model: it creates and owns Deployments, Services, and NetworkPolicies for each MCPServer CR, and watches ConfigMaps and Secrets referenced in MCPServer specs via field-indexed map functions for efficient cross-resource reconciliation. [source: internal/controller/mcpserver_controller.go:653-673, 640-651]

Security is implemented at multiple layers. The metrics endpoint uses controller-runtime's built-in authn/authz filter (`filters.WithAuthenticationAndAuthorization`) with self-signed TLS by default, conditionally enabled when `--metrics-secure=true` (the default). Health and readiness probes remain unauthenticated by design on a separate HTTP port. TLS configuration is environment-driven via TLS_MIN_VERSION and TLS_CIPHER_SUITES, with validation against Go's known cipher suite list. The operator can propagate its TLS settings to managed MCP server containers via the PROPAGATE_TLS_ENV_VARS flag, establishing a consistent TLS profile across the control and data planes. HTTP/2 is disabled by default to mitigate stream cancellation CVEs (GHSA-qppj-fm5r-hxr3, GHSA-4374-p667-p6c8). [source: cmd/main.go:75, 98-104, 139-144, 194-197, cmd/tlsconfig.go:30-63, 80-93]

RBAC follows a tiered model: the manager-role ClusterRole grants broad resource access for reconciliation (ConfigMaps, Secrets, Pods, Services, Deployments, NetworkPolicies, MCPServers, Events), while aggregated ClusterRoles (admin/editor/viewer) provide graduated access to MCPServer resources through Kubernetes built-in role aggregation. Leader election uses Lease-based coordination for high-availability deployments. [source: config/rbac/role.yaml:2, config/rbac/mcpserver_admin_role.yaml:11, cmd/main.go:170]

The operator has no internal platform dependencies on other RHOAI components; it operates independently against the Kubernetes API using the MCP Go SDK (github.com/modelcontextprotocol/go-sdk) and controller-runtime. [source: go.mod]

## Data Flows

The operator receives MCPServer CR events through the controller-runtime watch framework and reconciles each CR into a set of owned Kubernetes resources. The primary reconciliation flow reads the MCPServer spec, resolves referenced ConfigMaps and Secrets for configuration hashing, and creates or updates a Deployment, Service, and NetworkPolicy per MCPServer instance. ConfigMap and Secret watches use field-indexed map functions (`findMCPServersForConfigMap`, `findMCPServersForSecret`) to efficiently locate MCPServer resources referencing a given ConfigMap or Secret, triggering re-reconciliation when referenced configuration changes. Pod status is read to compute MCPServer status conditions. [source: internal/controller/mcpserver_controller.go:640-673, internal/controller/mcpserver_controller_conditions.go:114, internal/controller/mcpserver_controller_confighash.go:77, 109]

The operator communicates with the Kubernetes API server over TLS-secured HTTPS (port 6443) using in-cluster ServiceAccount authentication, with RBAC enforced by the mcp-lifecycle-operator-manager-role ClusterRole. Metrics are served on port 8443 with TLS encryption and TokenReview/SubjectAccessReview authentication via the controller-runtime metrics filter. Health and readiness probes are served on port 8081 over plain HTTP without authentication. [source: cmd/main.go:71, 75, 133-144, 164, 205, 209]
