## Purpose

**Short**: praxis-policy is the Praxis Policy Engine (PPE) — a Rust library workspace providing an extensible, plugin-based policy evaluation runtime for AI agent security, implementing JWT identity resolution, OAuth 2.0 token delegation (RFC 8693), OIDC CIBA human-in-the-loop approval, and multi-engine policy evaluation (Cedar, CEL, OPA) with fail-closed enforcement semantics. [source: crates/ppe/Cargo.toml:4-15, crates/ppe-core/Cargo.toml:6, builtins/plugins/identity-jwt/Cargo.toml:4-14]

**Detailed**: praxis-policy is a Rust workspace of 16 library crates organized as a facade (`praxis-policy`) over a plugin runtime core (`praxis-policy-core`), three policy decision point engines (Cedar, CEL, OPA via regorus), three security plugins (JWT identity, OAuth delegation, CIBA elicitation), a PII scanner, an audit logger, a Valkey-backed distributed session store, and supporting APL (Authorization Policy Language) crates. The workspace publishes as a single facade crate with Cargo features gating each builtin — a host application (such as praxis-proxy) depends on `praxis-policy` with the desired feature set and calls `install_builtins()` to register plugin factories. PPE does not expose HTTP or gRPC endpoints itself; outbound HTTP for JWKS refresh, OAuth token exchange, and CIBA flows is delegated through an `HttpTransport` trait seam that the host injects, and praxis-proxy supplies a Pingora-backed implementation. The engine enforces fail-closed semantics on identity resolution failures. [source: crates/ppe/Cargo.toml:4-15, 39-95, Cargo.toml:11-34, crates/ppe-core/Cargo.toml:4-6, 47-48]

## Architectural Analysis

The Praxis Policy Engine uses a hook-based plugin architecture with a 5-phase executor model. Hook types are open strings — hosts define hook points appropriate to their execution lifecycle, and PPE dispatches registered plugin handlers at each hook invocation. The framework is designed around three core security plugin families: **identity resolution** (JWT validation with configurable trusted issuers, claim mapping to SubjectExtension/ClientExtension), **token delegation** (RFC 8693 OAuth 2.0 token exchange with bounded coalescing cache via moka, zeroizing in-memory client credentials), and **elicitation** (OIDC CIBA backchannel authentication for human-in-the-loop approval of privileged agent operations). [source: crates/ppe-core/src/hooks/types.rs:4-14, builtins/plugins/identity-jwt/Cargo.toml:4-14, builtins/plugins/delegator-oauth/Cargo.toml:4-28, builtins/plugins/elicitation-ciba/Cargo.toml:4-26]

A critical design decision is the `HttpTransport` trait seam in `praxis-policy-core`: the engine defines HTTP request/response types (`http` crate, types only — no client, no runtime, no TLS) but never performs HTTP itself. The host application installs a transport implementation. Praxis-proxy injects its own Pingora-backed transport; an optional `http-hyper` feature in the facade crate provides a standalone hyper+rustls transport for hosts outside the Praxis ecosystem. This separation means the PPE's TLS and connection behavior are fully controlled by the host. [source: crates/ppe-core/Cargo.toml:46-48, crates/ppe/Cargo.toml:66-89]

The workspace enforces `unsafe_code = "forbid"` across all crates, uses Rust edition 2024 with resolver 3, and maintains MSRV 1.96. Sensitive credential material (OAuth client secrets, raw tokens) is wrapped with `zeroize` for in-memory clearing. The session store (Valkey-backed) is optional and excluded from default workspace members to avoid pulling the redis+TLS dependency stack into every build. [source: Cargo.toml:61-65, 177-203, builtins/plugins/delegator-oauth/Cargo.toml:60, builtins/session/valkey/Cargo.toml:9-15]

The crypto provider landscape is split: `jsonwebtoken` (JWT verification) selects `aws-lc-rs` explicitly to avoid the RUSTSEC-2023-0071 advisory in the `rsa` crate's pure-Rust path, while the `http-hyper` TLS transport and the Valkey session store use `rustls` with the `ring` backend. Neither provider is FIPS-validated by default; aws-lc-rs supports a FIPS build mode but it requires specific build-time configuration not present in this repository. [source: builtins/plugins/identity-jwt/Cargo.toml:35-43, crates/ppe/Cargo.toml:135-147, builtins/session/valkey/Cargo.toml:43-59]
