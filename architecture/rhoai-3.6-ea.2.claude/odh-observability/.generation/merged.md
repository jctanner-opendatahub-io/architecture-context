## Purpose

**Short**: odh-observability is a Kubernetes operator that manages the end-to-end observability stack — metrics collection, distributed tracing, usage-log forwarding, and alerting — for Red Hat OpenShift AI platform components. [source: api/v1alpha1/monitoring_types.go:37-70, cmd/main.go:62-156]

**Detailed**: odh-observability is a controller-runtime operator that reconciles a singleton cluster-scoped `Monitoring` custom resource (services.platform.opendatahub.io/v1alpha1). The operator deploys and manages Prometheus monitoring stacks, OpenTelemetry collectors, kube-rbac-proxy-secured metric proxies, and optional integrations with Tempo (traces), LokiStack (logs/usage-logs), and Prometheus alerting rules. It templates Kubernetes resources — Deployments, Services, Routes, RBAC, Secrets, and webhook configurations — via the `odh-platform-utilities` deployer using server-side apply with deterministic ordering. The operator watches 15+ Kubernetes resource types to reconcile the full monitoring surface, and exposes two kube-rbac-proxy-protected Routes for cluster-wide and namespace-scoped Prometheus queries. TLS configuration is derived from the OpenShift cluster APIServer TLS security profile, ensuring platform-consistent cipher suites and minimum TLS versions across all proxy components. [source: cmd/main.go:62-156, api/v1alpha1/monitoring_types.go:37-70, pkg/tls/profile.go:150-163, internal/controller/resources/data-science-prometheus-cluster-proxy.tmpl.yaml:58-97]

## Architectural Analysis

odh-observability follows the reconciler-templates pattern common to RHOAI platform operators: a single `MonitoringReconciler` watches the `Monitoring` CR and renders Go templates into a broad set of Kubernetes resources using the `odh-platform-utilities` deployer with server-side apply. The operator does not embed business logic for metrics collection or tracing; instead, it orchestrates third-party operators (prometheus-operator for MonitoringStacks, Tempo operator for traces, ClusterLogForwarder for logs) by creating their CRs and supporting RBAC, network, and TLS plumbing. [source: cmd/main.go:110-128, api/v1alpha1/monitoring_types.go:37-70]

The security architecture centers on kube-rbac-proxy as the authentication and authorization enforcement point for all externally-exposed Prometheus endpoints. The cluster-wide proxy authorizes requests via SubjectAccessReview against `metrics.k8s.io/nodes:get`, while the namespace proxy uses query-parameter rewriting to enforce namespace-scoped authorization against `metrics.k8s.io/pods`. Both proxies delegate TokenReview and SubjectAccessReview to the Kubernetes API via the `system:auth-delegator` ClusterRole. TLS settings (minimum version and cipher suites) are dynamically derived from the cluster APIServer's TLSSecurityProfile, with an Intermediate profile floor for unsupported versions. [source: internal/controller/resources/data-science-prometheus-cluster-proxy.tmpl.yaml:51-56,78-97, internal/controller/resources/data-science-prometheus-namespace-proxy.tmpl.yaml:74-84,109-120, pkg/tls/profile.go:150-163]

The operator uses the `odh-platform-utilities` library for two distinct concerns: (1) the `deploy` package provides server-side-apply deployment with caching and deterministic ordering (`cmd/main.go:110-115`), and (2) the `api/common` package provides the `PlatformObject` interface and shared status/condition types that the `Monitoring` CR implements (`api/v1alpha1/monitoring_types.go:20,34,42`). This dependency couples the CRD schema to the platform-utilities API contract. The operator also imports `openshift/library-go` for OpenSSL-to-IANA cipher suite translation in the TLS profile resolution path. [source: cmd/main.go:23,110-115, api/v1alpha1/monitoring_types.go:20,34, pkg/tls/profile.go:9,109-118]

The FIPS compliance posture is strong: the Konflux Dockerfile builds with `CGO_ENABLED=1`, `GOEXPERIMENT=strictfipsruntime`, and `-tags strictfipsruntime`, producing a dynamically-linked binary on a `ubi9/ubi-minimal-pqc` (post-quantum crypto) base image. At the application level, TLS configuration is delegated to the cluster APIServer profile system rather than hardcoding cipher suites, and cipher mapping uses `openshift/library-go` crypto utilities. [source: Dockerfiles/Dockerfile.konflux:20,22, pkg/tls/profile.go:101-127]

## Data Flows

- **Metrics query path:** External clients access Prometheus metrics through two kube-rbac-proxy-protected Routes. The cluster-wide Route (`data-science-prometheus-cluster-proxy`) terminates TLS at the Route, re-encrypts to kube-rbac-proxy on port 8443, which performs SubjectAccessReview authorization against `metrics.k8s.io/nodes:get` and proxies authorized requests upstream to `prometheus-operated:9090` via mTLS (client cert + CA verification). The namespace-scoped Route (`data-science-prometheus-route`) follows a similar path through a separate kube-rbac-proxy that rewrites the `namespace` query parameter into a namespace-scoped SAR against `metrics.k8s.io/pods`. [source: internal/controller/resources/data-science-prometheus-cluster-proxy.tmpl.yaml:78-97,187-199, internal/controller/resources/data-science-prometheus-namespace-proxy.tmpl.yaml:74-84,109-120]
- **Reconciliation flow:** The operator's `MonitoringReconciler` watches the singleton `Monitoring` CR and 15+ related resource types (ConfigMaps, Secrets, Deployments, Routes, RBAC, NetworkPolicies, CRDs, APIServer). On reconciliation, it reads the cluster APIServer TLS profile, renders Go templates with computed TLS settings, and applies the resulting manifests via the odh-platform-utilities deployer using server-side apply. [source: cmd/main.go:110-128, pkg/tls/profile.go:150-163]
- **Webhook injection:** When enabled, a mutating admission webhook intercepts PodMonitor and ServiceMonitor CREATE/UPDATE operations to inject monitoring labels. The webhook server listens on port 9443 with TLS certs from a configurable directory. [source: cmd/main.go:97-102,131-139]
- **Security context:** Authentication is enforced at two layers: kube-rbac-proxy performs SubjectAccessReview for all externally-exposed metric endpoints, while health/readyz probes on port 8081 are unauthenticated by design. TLS certificates are provisioned via OpenShift service-serving certificate annotations, and 9 Secrets manage TLS material for proxies, collectors, and Prometheus. [source: internal/controller/resources/data-science-prometheus-cluster-proxy.tmpl.yaml:51-56,78-97,176, cmd/main.go:142-146]
