## Purpose

**Short**: Model Registry provides a centralized metadata store for ML models, versions, and artifacts, with a Go REST proxy, a BFF-backed UI, a controller-runtime operator that reconciles KServe InferenceService state, and an async-upload Python job for model storage operations. **Detailed**: Model Registry is a multi-component system that gives ML practitioners a central place to register, version, and track model artifacts. The core Go binary (`model-registry`) runs as an HTTP proxy (port 8080) backed by a relational database (PostgreSQL or MySQL via GORM). A Go BFF server (`bff`) provides the UI backend on port 4000, handling authentication via configurable Bearer tokens or internal ServiceAccount tokens and proxying Kubernetes resource operations (ConfigMaps, Secrets, Jobs, SubjectAccessReviews). A controller-runtime operator watches KServe `InferenceService` resources to synchronize model serving state back to the registry, reading Service objects to discover registry endpoints. An async-upload Python job (`job.entrypoint`) copies models between storage backends (S3 via boto3, OCI registries via ORAS/skopeo) and registers them, with Sigstore-based model signing support. Istio AuthorizationPolicies enforce per-service access control, while the operator metrics endpoint uses controller-runtime's TokenReview/SubjectAccessReview authentication filter with self-signed TLS. The Go binary is built with FIPS-compliant settings (`GOEXPERIMENT=strictfipsruntime`, dynamic linking) on a UBI post-quantum crypto base image. ## Architectural Analysis

Model Registry follows a multi-tier architecture with clear separation between data storage, API serving, UI, and platform integration. The core `model-registry` binary acts as an HTTP proxy fronting a GORM-backed relational store (PostgreSQL or MySQL), exposing a REST API for model metadata CRUD. The UI layer is served through a Go BFF (`bff`) that authenticates requests via a configurable `auth-method` flag — either validating Bearer tokens from an `Authorization` header or using internal ServiceAccount tokens — and forwards them to both the registry API and the Kubernetes API for resource management (ConfigMaps, Secrets, Jobs, SubjectAccessReviews). [source: clients/ui/bff/cmd/main.go:56-58, internal/platform/tls/config.go:64-68]

The controller-runtime operator provides the bridge to KServe: an `InferenceServiceController` watches `serving.kserve.io/v1beta1/InferenceService` resources and reconciles their serving URLs back into the registry by discovering model-registry Service objects via label selectors. A separate `InferenceServiceReconciler` in `cmd/controller` delegates to the same controller logic, allowing the operator deployment (`controller-controller-manager`) to manage the watch lifecycle. The controller uses RBAC to access InferenceServices (get, list, patch, update, watch) and their finalizers, plus core Services (get, list, watch). [source: pkg/inferenceservice-controller/controller.go:249-253, 306-311, cmd/controller/internal/controllers/inferenceservice_controller.go:43-47, manifests/kustomize/options/controller/rbac/role.yaml:2]

Network security is layered: Istio VirtualServices route external traffic to the registry, catalog, and UI services, while Istio AuthorizationPolicies restrict access — the registry API requires namespace membership (kubeflow), principal identity (istio-ingressgateway SA), and a JWT authorization header; the UI requires only principal identity. The controller metrics endpoint (`:8443`) uses controller-runtime's built-in authn/authz filter with self-signed TLS, gated by `controller-metrics-auth-role` RBAC. Health and readiness probes (`:8081`) are unauthenticated by design. [source: manifests/kustomize/options/istio/istio-authorization-policy.yaml:1, manifests/kustomize/options/ui/overlays/istio/authorization-policy-ui.yaml:1, cmd/controller/main.go:104, 160, 164]

The Go components are built with FIPS-compliant settings (`CGO_ENABLED=1`, `GOEXPERIMENT=strictfipsruntime`, `-tags strictfipsruntime`) on UBI 9 with a post-quantum crypto runtime base (`ubi-minimal-pqc`). The TLS configuration enforces a minimum of TLS 1.2, supports configurable cipher suites restricted to FIPS-approved algorithms, and explicitly rejects any cipher suite marked insecure by the Go standard library. The async-upload Python job runs on an AIPCC CPU base image with system OpenSSL, using `cryptography` and `pyopenssl` for TLS and `pyjwt` for JWT operations. ## Data Flows

- **User request path:** External requests arrive via Istio VirtualServices (model-registry, model-catalog, model-registry-ui) routing to backend services in the kubeflow namespace.
