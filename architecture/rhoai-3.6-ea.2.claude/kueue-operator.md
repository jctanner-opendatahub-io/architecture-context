## Purpose

**Short**: OpenShift operator that deploys and manages the Kueue workload queuing controller, providing job queuing, fair-sharing, and resource quota management for batch and ML training workloads across multiple job frameworks. [source: pkg/operator/starter.go:28, bindata/assets/kueue-operator/deployment.yaml:1, bindata/assets/kueue-operator/clusterroles/clusterrole-manager-role.yaml:2]

**Detailed**: kueue-operator implements a two-tier operator pattern using the OpenShift library-go framework. The first tier is the openshift-kueue-operator Deployment (2 replicas, system-cluster-critical priority), which watches for `Kueue` CR instances on the `kueue.openshift.io` API group and reconciles the second tier — the kueue-controller-manager Deployment that runs the upstream Kueue controller binary. The operator creates all dependent resources including CRDs, RBAC roles, webhooks, services, and the controller deployment in the `openshift-kueue-operator` namespace. [source: pkg/operator/starter.go:28-101, deploy/07_deployment.yaml:1, bindata/assets/kueue-operator/deployment.yaml:1]

The kueue-controller-manager exposes a substantial webhook surface (17 mutating + 17 validating admission webhooks) that intercepts workload creation and updates for Kubernetes batch Jobs, Kubeflow training jobs (MPIJob, PyTorchJob, TFJob, XGBoostJob, PaddleJob), Ray clusters/jobs, AppWrappers, JobSets, LeaderWorkerSets, Deployments, StatefulSets, and Pods. It also provides a visibility API server for pending workload queries and a metrics endpoint. The operator depends on cert-manager for webhook TLS certificate provisioning and prometheus-operator for metrics collection via ServiceMonitor CRs. [source: bindata/assets/kueue-operator/mutatingwebhook.yaml:1, bindata/assets/kueue-operator/validatingwebhook.yaml:1, deploy/02_clusterrole.yaml:93-139]

## Architectural Analysis

kueue-operator follows the standard OpenShift library-go operator pattern where the operator binary (`cmd/kueue-operator`) is a Cobra CLI application that launches a controller using `controllercmd.ControllerContext` to manage the lifecycle of the Kueue controller-manager. The `RunOperator` function in `pkg/operator/starter.go` constructs multiple Kubernetes clients — including a discovery client, dynamic client, OpenShift route client, and CRD client — all authenticated via in-cluster ServiceAccount tokens inherited from the controller context's kubeconfig. The operator watches for `Kueue` CRs (kueue.openshift.io/v1) and reconciles a `TargetConfigReconciler` that applies the bundled assets (CRDs, deployments, RBAC, webhooks, services) into the target namespace. [source: pkg/operator/starter.go:28-101, cmd/kueue-operator/main.go:12]

The operator deployment runs 2 replicas with `system-cluster-critical` priority class, ensuring high availability for the control plane. It uses `readOnlyRootFilesystem: true` and drops all Linux capabilities. The operand (kueue-controller-manager) runs as a single replica and exposes four network surfaces: webhook admission on port 9443 (TLS-encrypted via cert-manager-provisioned certificates mounted from `kueue-webhook-server-cert` secret), a visibility API server on port 8082 for querying pending workloads, Prometheus metrics on port 8443 with TokenReview/SubjectAccessReview-based authentication, and health/readiness probes on port 8081. [source: deploy/07_deployment.yaml:1-54, bindata/assets/kueue-operator/deployment.yaml:1-89]

The webhook surface is architecturally significant: 34 webhooks with `Fail` failure policy intercept workload lifecycle events across 7 distinct job frameworks (batch/v1 Jobs, kubeflow.org training jobs, ray.io clusters/jobs, jobset.x-k8s.io JobSets, leaderworkerset.x-k8s.io LeaderWorkerSets, workload.codeflare.dev AppWrappers, and core Pods/Deployments/StatefulSets). This broad interception scope means Kueue availability directly affects workload creation across the cluster. The webhooks are served by a single Service (`kueue-webhook-service`) on port 443 mapping to container port 9443. [source: bindata/assets/kueue-operator/mutatingwebhook.yaml:1, bindata/assets/kueue-operator/validatingwebhook.yaml:1, bindata/assets/kueue-operator/webhook-service.yaml:1]

FIPS compliance is enforced at build time via `GO_BUILD_FLAGS :=-tags strictfipsruntime` in the Makefile, using the Red Hat Go builder on RHEL 9 which provides dynamic linking with OpenSSL. The runtime image is UBI 9 minimal, which includes the system OpenSSL library. [source: Makefile:12, Dockerfile:1, Dockerfile:6]

## Data Flows

- **Operator reconciliation flow:** The openshift-kueue-operator watches `Kueue` CRs (kueue.openshift.io/v1) via the Kubernetes API and reconciles the kueue-controller-manager Deployment along with its dependent resources (CRDs, RBAC, services, webhooks, configmaps). The operator authenticates to the API server using the `openshift-kueue-operator` ServiceAccount token. [source: pkg/operator/starter.go:28-101, deploy/07_deployment.yaml:1]
- **Webhook admission flow:** The kube-apiserver sends admission requests to the `kueue-webhook-service` (port 443 -> target 9443) over TLS for workload creation/update events across 7 job frameworks. The kueue-controller-manager processes these via 34 mutating and validating webhooks, applying queue labels and enforcing queue policies. Webhook TLS is provisioned by cert-manager certificates. [source: bindata/assets/kueue-operator/webhook-service.yaml:1, bindata/assets/kueue-operator/mutatingwebhook.yaml:1, bindata/assets/kueue-operator/validatingwebhook.yaml:1]
- **Queue management flow:** The kueue-controller-manager watches ClusterQueue, LocalQueue, Workload, and ResourceFlavor CRs to manage job scheduling. It reads node resources for capacity-aware scheduling and manages workload lifecycle across supported job frameworks via the `kueue-manager-role` ClusterRole (36 RBAC rules). [source: bindata/assets/kueue-operator/clusterroles/clusterrole-manager-role.yaml:2]
- **Observability flow:** Metrics are exported on port 8443 via `kueue-controller-manager-metrics-service`, protected by TokenReview/SubjectAccessReview authentication (kueue-metrics-auth-role). The pending workloads visibility API is exposed on port 8082 via `kueue-visibility-server`. Prometheus scrapes metrics via a ServiceMonitor CR managed by the operator. [source: bindata/assets/kueue-operator/controller-manager-metrics-service.yaml:1, bindata/assets/kueue-operator/visibility-server.yaml:1, deploy/02_clusterrole.yaml:93-104]
