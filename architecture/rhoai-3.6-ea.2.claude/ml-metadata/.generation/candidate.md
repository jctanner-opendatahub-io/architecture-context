## Purpose

**Short**: ML Metadata (MLMD) is a gRPC metadata store server that records and retrieves metadata associated with ML workflows, exposing the MetadataStoreService on port 8080/TCP with configurable database backends (MySQL, PostgreSQL, SQLite). [source: ml_metadata/proto/metadata_store_service.proto:1142, ml_metadata/tools/docker_server/Dockerfile.konflux:47, ml_metadata/proto/metadata_store.proto:788-798]

**Detailed**: ML Metadata provides a standalone gRPC server (`metadata_store_server`) that manages artifact, execution, and context metadata for ML pipelines. The server is a C++ binary built with Bazel from the `//ml_metadata/metadata_store:metadata_store_server` target, exposing the `MetadataStoreService` gRPC API on a configurable port (default 8080). The repository also produces a Python client library (`ml_metadata` package) for programmatic access. The server supports MySQL, PostgreSQL, and SQLite database backends via its `MetadataStoreServerConfig` protobuf configuration, with optional SSL/TLS for both the gRPC channel and database connections. The downstream Red Hat build uses a multi-stage Dockerfile with a UBI9 base image, running as a non-root user (UID 65534). [source: ml_metadata/tools/docker_server/Dockerfile.konflux:29-34, ml_metadata/tools/docker_server/Dockerfile.konflux:56-59, ml_metadata/proto/metadata_store.proto:852-874, ml_metadata/proto/metadata_store.proto:607-656]

## Architectural Analysis

ML Metadata is a Google-originated component that serves as the lineage and metadata backbone for ML pipeline systems such as Kubeflow Pipelines and its RHOAI counterpart (Data Science Pipelines). The server binary is compiled as a statically-linked C++ application via Bazel, despite the repository also containing a Python client SDK — the runtime server has no Python dependency. The three-tier repo lineage (Google upstream → opendatahub-io midstream → red-hat-data-services downstream) uses auto-merge synchronization.

The gRPC `MetadataStoreService` API exposes a comprehensive CRUD and lineage-query interface for ML metadata entities: Artifacts, Executions, Contexts, Events, and their type hierarchies. The server's `MetadataStoreServerConfig` protobuf supports optional mutual TLS via `SSLConfig` (server key, server certificate, custom CA, and client certificate verification), but the default deployment uses an insecure gRPC channel with authentication delegated to the platform's network layer. No application-level authentication or authorization mechanism exists within the server itself.

The Konflux build uses a `ubi9/ubi-minimal-pqc` runtime base image, which bundles system OpenSSL. The C++ binary links against OpenSSL at build time (via `openssl-devel` in the builder stage), so it inherits the platform's cryptographic provider. However, there are no explicit FIPS mode build flags or runtime configuration for the C++ binary, and no FIPS-specific Bazel build options are present. The server runs as non-root (UID 65534) in the container. The MariaDB client connector library (`libmysqlclient`) is bundled as a third-party dependency for MySQL backend support.
