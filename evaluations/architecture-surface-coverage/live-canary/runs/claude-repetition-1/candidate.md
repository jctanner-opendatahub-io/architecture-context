## Purpose

**Short**: The rhods-operator is the central lifecycle and platform-services operator for Red Hat OpenShift AI, managing component reconciliation, Gateway API ingress with OAuth/OIDC authentication, admission webhooks, and cloud-manager infrastructure across 14 custom resource definitions. [source: cmd/main.go:480-546, api/services/v1alpha1/gateway_types.go:27-33, Dockerfiles/Dockerfile.konflux:58-61]

**Detailed**: rhods-operator is the downstream RHOAI distribution of the opendatahub-operator. It runs as a controller-runtime operator (entrypoint `/manager`) managing the DataScienceCluster, DSCInitialization, and GatewayConfig singleton CRDs as its primary reconciliation targets. The operator orchestrates platform components—DataSciencePipelines, Kueue, Ray, TrustyAI, KServe, ModelRegistry, and Dashboard—through component-handler controllers that own Deployments, Services, RBAC, and monitoring resources. A dedicated gateway service controller provisions a `data-science-gateway` Gateway API resource with a kube-auth-proxy deployment that supports integrated OpenShift OAuth (via OAuthClient `data-science`), external OIDC providers, and Kubernetes service-account TokenReview validation. The auth service controller watches the `models-as-a-service` and `kuadrant-system` namespaces to reconcile platform-wide RBAC roles for admin and allowed user groups. A separate cloudmanager binary manages AWSKubernetesEngine, AzureKubernetesEngine, and CoreWeaveKubernetesEngine CRDs for multi-cloud infrastructure. The operator serves 10 admission webhooks (validating and mutating for DataScienceCluster v1/v2, DSCInitialization v1/v2, HardwareProfile, AcceleratorProfile, and PodMonitor injection) on port 9443 with TLS identity established by the OpenShift service-ca operator. Metrics are conditionally secured with controller-runtime authentication and authorization filters when `MetricsSecure` is enabled. The Konflux build uses `CGO_ENABLED=1` with `GOEXPERIMENT=strictfipsruntime` for FIPS-capable dynamic linking on a UBI 9 PQC-enabled base image. ## Architectural Analysis

The rhods-operator follows a hub-and-spoke controller architecture where a single operator deployment manages the full RHOAI platform lifecycle. The `DataScienceCluster` CR serves as the top-level intent declaration; its reconciler delegates to per-component handlers (DataSciencePipelines, Kueue, Ray, TrustyAI, KServe, ModelRegistry, Dashboard) that own their Deployments, Services, RBAC, and monitoring resources through Kustomize-based manifests. The `DSCInitialization` CR handles one-time cluster preparation including namespace creation, feature trackers, and GatewayConfig bootstrapping. [source: cmd/main.go:480-546, internal/controller/services/auth/auth_controller.go:56-84]

The gateway service introduces a significant architectural pattern: a `kube-auth-proxy` deployment fronts the platform's Gateway API ingress (`data-science-gateway`) with three authentication modes. When the cluster uses integrated OpenShift authentication, the proxy configures an OAuthClient named `data-science` for browser-based OAuth flows. When external OIDC is configured via `GatewayConfigSpec.OIDC`, the proxy uses the specified issuer URL and client credentials. In both modes, Kubernetes service-account TokenReview validation is enabled by default (`EnableK8sTokenValidation: true`) to allow programmatic access alongside human authentication. The auth service controller watches the `models-as-a-service` and `kuadrant-system` namespaces to detect the presence of Kuadrant API gateway policy and MaaS capabilities, reconciling RBAC ClusterRoles and Roles that grant admin groups access across DataScienceCluster, ModelRegistry, Feast, HardwareProfile, ServingRuntime, and NIM Account resources. [source: api/services/v1alpha1/gateway_types.go:35-131, internal/controller/services/gateway/gateway_support.go:31-50, internal/controller/services/auth/auth_controller.go:63-76]

The operator applies the cluster's TLS security profile (fetched from the OpenShift APIServer configuration) to both its webhook server (port 9443) and metrics server (port 8443). Metrics security is conditional: when `MetricsSecure` is true, the controller-runtime `filters.WithAuthenticationAndAuthorization` filter provider enforces Kubernetes authentication and authorization on the `/metrics` endpoint. The webhook server identity is established by the OpenShift service-ca operator, which provisions the `opendatahub-operator-controller-webhook-cert` TLS secret and injects the CA bundle into webhook configurations. The build pipeline uses `GOEXPERIMENT=strictfipsruntime` with `CGO_ENABLED=1` on a UBI 9 PQC-enabled base image, establishing FIPS-capable cryptographic linkage, though runtime FIPS compliance ultimately depends on the host node's FIPS mode activation. ## Data Flows

- **Admission and webhook flow:** The Kubernetes API server sends admission requests (CREATE, UPDATE, DELETE) to the operator's webhook server on port 9443 over TLS. The webhook server identity is established by the OpenShift service-ca operator via the `opendatahub-operator-controller-webhook-cert` TLS secret. Ten admission webhooks validate and mutate DataScienceCluster (v1/v2), DSCInitialization (v1/v2), AcceleratorProfile, HardwareProfile, and PodMonitor resources, plus conversion webhooks for DataScienceCluster CRD version migration. [source: cmd/main.go:501-504, config/webhook/service.yaml:1]
- **Gateway ingress flow:** External user requests arrive at the `data-science-gateway` Gateway API resource (namespace `openshift-ingress`) via OpenShift Routes or LoadBalancer. The kube-auth-proxy deployment intercepts requests, performing OAuth/OIDC authentication and optional Kubernetes TokenReview validation, then forwards authenticated traffic to backend services via HTTPRoute rules. The auth proxy calculates a hash of the `kube-auth-proxy-creds` secret to trigger pod restarts on credential rotation. [source: internal/controller/services/gateway/gateway_controller_actions.go:288-302, internal/controller/services/gateway/gateway_support.go:38-49, api/services/v1alpha1/gateway_types.go:59-131]
- **Component reconciliation flow:** The DataScienceCluster reconciler reads component enablement state and delegates to per-component handlers. Each handler owns its Deployments, Services, RBAC, ConfigMaps, and monitoring resources. The auth service controller watches the `models-as-a-service` and `kuadrant-system` namespaces and reconciles RBAC roles granting admin groups access to platform CRDs. [source: internal/controller/services/auth/auth_controller.go:56-84]
- **Metrics and health flow:** The operator exposes health probes at `:8081/healthz` and `:8081/readyz` without authentication. The metrics endpoint at port 8443 is conditionally secured: when `MetricsSecure` is true, controller-runtime `WithAuthenticationAndAuthorization` filters require Kubernetes authentication and RBAC authorization to access metrics data. [source: cmd/main.go:485-500, config/default/metrics_service_patch.yaml:3]
